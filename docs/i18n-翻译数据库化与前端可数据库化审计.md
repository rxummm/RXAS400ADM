## 一、i18n 翻译数据库化方案

### 1.1 问题背景

前端翻译原先存储在静态 TypeScript 文件中（`zh-CN.ts`、`menu.ts`、`bpcs.ts` 等），任何翻译修改都需要：修改 `.ts` → 重新构建 → 重新部署。即使是「改一个按钮文字」也需要完整前端发布流程。

### 1.2 方案：使用 `rx_i18n` 表

所有业务模块翻译迁移到 MySQL `rx_i18n` 表，前端登录后通过 API 加载并 `mergeLocaleMessage()` 合并进 vue-i18n。

**覆盖范围**：

| 层 | 加载时机 | 覆盖范围 | 数量 |
|----|---------|---------|------|
| 静态 TS（`common.ts`/`menu.ts`） | App 启动时同步加载 | `login/layout/error/common/menu` 等基础 namespace | **477 个 key** |
| DB（`rx_i18n` 表） | 登录后异步加载 `GET /api/v1/i18n` | **所有**业务模块翻译 | **2664 个 key** |

**静态 TS 文件保留的 namespace**（登录前 fallback）：
- `login.*` / `layout.*` / `theme.*` / `tokenRefresh.*` / `status.*` / `connection.*`
- `error.*`（42 个错误码）/ `common.*`（90 个共享按钮/标签）/ `col.*`（6 个列缩写）
- `table.*` / `confirm.*` / `empty.*` / `contextMenu.*` / `export.*` / `profile.*`
- `menu.*`（154 个菜单标签）/ `menuType.*`

**DB 覆盖的业务模块**（部分列举）：
- `bpcs.*` / `monitor.*` / `alertRules.*` / `assets.*` / `schedule.*` / `scripts.*`
- `jobs.*` / `users.*` / `role.*` / `permissions.*` / `notice.*` / `webhooks.*`
- `config.*` / `docs.*` / `reports.*` / `health.*` / `topology.*` 等

### 1.3 运行时逻辑

```
登录 → loadDbTranslations() → GET /api/v1/i18n?lang=zh-CN
  → mergeLocaleMessage(lang, data) → DB 翻译覆盖静态 fallback
  → 失败时静默降级为静态文案
```

**覆盖规则**（共存期安全）：

| 场景 | 行为 |
|------|------|
| DB 有、静态文件也有 | **DB 优先** |
| DB 有、静态文件无 | DB 生效 |
| DB 无、静态文件有 | 静态文件生效（fallback） |
| DB 无、静态文件也无 | 显示 key 原文 |

### 1.4 数据库表结构

```sql
CREATE TABLE rx_i18n (
    i18n_key   VARCHAR(100) NOT NULL,
    lang       VARCHAR(10)  NOT NULL COMMENT 'zh-CN / en-US',
    text       VARCHAR(500) NOT NULL,
    module     VARCHAR(30)  NOT NULL DEFAULT 'common',
    updated_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    updated_by VARCHAR(50)  NULL,
    PRIMARY KEY (i18n_key, lang),
    INDEX idx_module (module)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='动态翻译表';
```

## 二、i18n DB 翻译时序问题修复

### 2.1 问题现象

登录后控制台反复输出：
```
As400ServerSelector.vue:19 [intlify] Not found 'as400Server.hint' key in 'zh' locale messages.
NotificationBell.vue:4 [intlify] Not found 'notification.title' key in 'zh' locale messages.
```

这些 key 在 V82 DB seed 中**已存在**，是时序问题导致的。

### 2.2 根因分析

**登录时序问题**：`applyLogin()` 内 `void loadDbTranslations()` 是 fire-and-forget，路由守卫只 await `fetchMenus()` 不 await 翻译加载。布局组件在 DB 翻译加载完成前就渲染了。

**语言切换时序问题**：`toggleLocale()` 先同步调用 `setLocale(next)` 切换 locale（触发 Vue 重渲染），再异步调用 `loadDynamicI18n(next)` 加载翻译。重渲染时目标语言的 DB 翻译尚未加载。

### 2.3 修复方案（3 处修改）

#### 1. `stores/user.ts` — 并发去重

```typescript
let i18nFetchPromise: Promise<void> | null = null

async loadDbTranslations() {
  if (i18nFetchPromise) return i18nFetchPromise
  i18nFetchPromise = this._doLoadDbTranslations().finally(() => {
    i18nFetchPromise = null
  })
  return i18nFetchPromise
}
```

#### 2. `router/index.ts` — 路由守卫 await 翻译加载

```typescript
if (userStore.isLoggedIn && PROTECTED_PATHS.has(to.path)) {
  if (!userStore.menus.length) {
    await userStore.fetchMenus()
  }
  try {
    await userStore.loadDbTranslations()
  } catch { /* 翻译加载失败不阻断导航 */ }
}
```

#### 3. `layout/index.vue` — 语言切换先加载翻译再切 locale

```typescript
const toggleLocale = async () => {
  const next = locale.value === 'zh-CN' ? 'en-US' : 'zh-CN'
  await loadDynamicI18n(next)   // 先加载翻译
  setLocale(next)                // 再切换（重渲染时翻译已就绪）
}
```

### 2.4 修复后时序

```
登录：
  路由守卫 → await fetchMenus() → await loadDbTranslations() → 布局渲染 ✅

语言切换：
  toggleLocale() → await loadDynamicI18n(next) → setLocale(next) → 重渲染 ✅
```

### 2.5 验证步骤

1. `cd frontend && npm run build` — 构建通过
2. 重启 dev server（`npm run dev`）
3. 浏览器 Ctrl+Shift+R 强制刷新
4. 控制台无 `[intlify] Not found` 警告
5. 点击语言切换按钮（中↔英），切换后控制台无新警告
