## 三、功能点分析

### 3.1 认证与授权（security 模块）

**实现亮点：**
- Spring Security 6 + JWT（jjwt 0.12.6）无状态认证
- 登录失败锁定（5 次/15 分钟）+ IP 限流
- Token 黑名单（登出吊销）
- @PreAuthorize 214 处全覆盖
- CORS 白名单配置化（非通配符）
- CSP 纵深防御（script-src 'self'）
- Referrer-Policy + Permissions-Policy

**可优化项：**
1. **Token 刷新机制缺失**：当前 JWT 有效期 24 小时，过期后用户需重新登录。建议实现 refresh token 或 sliding window 机制
2. **密码策略硬编码**：`PasswordPolicy.validate()` 内联了 8 位+字母数字规则，应配置化（`rxas400.security.password.min-length` 等）
3. **会话固定攻击防护**：虽然无状态 JWT 不存在此问题，但缺少 token 绑定（如 IP/User-Agent 绑定）

### 3.2 多 AS400 服务器路由

**实现亮点：**
- AS400Client 接口 + Mock/JTOpen 双实现
- As400ServerContextHolder（ThreadLocal）+ X-AS400-Server 头路由
- AS400ClientProvider 按服务器 ID 获取客户端
- 连接池管理（JTOpenConnectionState）

**可优化项：**
1. **连接池健康检查缺失**：JTOpen 连接可能因 AS400 端断开而失效，缺少主动探活机制
2. **服务器权重/优先级**：当前无负载均衡策略，多服务器仅按 ID 路由
3. **连接超时配置**：JTOpen 连接超时未在 application.yml 中暴露

### 3.3 监控与告警（monitor 模块）

**实现亮点：**
- 定时采集（CollectorScheduler）+ WebSocket STOMP 推送
- AlertEngine 告警引擎（阈值/持续时间/冷却期）
- 指标保留策略（30 天自动清理）
- 告警规则 CRUD + 启用/禁用

**可优化项：**
1. **采集器并发安全隐患**：CollectorScheduler 线程池已加 @PreDestroy，但 AlertEngine.BreachState 的 volatile 修复需验证多线程场景
2. **告警通知渠道单一**：当前仅数据库记录，缺少邮件/Webhook/钉钉等外部通知
3. **指标聚合缺失**：Dashboard overview 已合并为单条 SQL，但缺少小时/天级预聚合（时间窗口查询性能）

### 3.4 作业管理（as400 模块）

**实现亮点：**
- JobController 完整 CRUD + 结束/释放/挂起/应答
- 作业依赖图（JobDependencyController）
- SLA 监控（JobSlaController）
- MSGW 消息队列查看与应答

**可优化项：**
1. **作业名 URL 编码风险**：`GET /jobs/{name}/{user}/{number}` 路径变量可能包含 `/`（如 `QUSER/QZDASOINIT/0123`），应改为 `@RequestParam`
2. **作业状态轮询**：前端 10 秒轮询作业列表，缺少 WebSocket 推送作业状态变更

### 3.5 IFS 文件管理

**实现亮点：**
- 路径沙箱校验（IfsPathValidator）
- 文件上传/下载/创建目录/删除/恢复
- 文件内容预览（文本文件）

**可优化项：**
1. **大文件读取风险**：`readIfsFile` 无文件大小限制，大文件可能 OOM
2. **文件类型校验缺失**：上传时未校验文件类型，可能上传可执行文件

### 3.6 编译服务（compile 模块）

**实现亮点：**
- 支持 RPG/CL/Cobol/DDS 等编译类型
- 编译命令白名单校验
- 编译结果解析与日志

**可优化项：**
1. **编译超时未配置**：长时间编译可能阻塞线程
2. **编译产物存储**：编译日志仅内存/日志文件，无持久化查询能力

### 3.7 报表服务

**实现亮点：**
- 定时报表生成（ReportScheduleQuartzJob）
- Excel（Apache POI）+ PDF（OpenPDF）导出
- 报表模板管理

**可优化项：**
1. **Quartz 集群调度**：当前 RAMJobStore，不支持多节点集群
2. **报表缓存缺失**：相同参数重复生成无缓存

## 四、代码质量分析

### 4.1 分层规范（✅ 优秀）

| 检查项 | 结果 | 标准 |
|--------|------|------|
| Controller 注入 Mapper | 0 处 | ❌ 禁止 |
| Controller new QueryWrapper | 0 处 | ❌ 禁止 |
| 写接口用 DTO | ✅ | ❌ 禁止 Entity 入参 |
| 返回 VO | ⚠️ 8 个 VO | ❌ 禁止直返 Entity |

**遗留问题：**
- 仅 8 个 VO，部分 Admin-only CRUD 直接返回 Entity（如 DictController、ConfigController）
- 新增接口已全部走 VO，但存量未清理

### 4.2 命名规范（✅ 良好）

| 类型 | 命名模式 | 示例 | 评价 |
|------|---------|------|------|
| Controller | `{Module}Controller` | JobController | ✅ |
| Service | `I{Module}Service` | IJobService | ✅ |
| Mapper | `{Entity}Mapper` | SysUserMapper | ✅ |
| DTO | `{Action}{Entity}DTO` | CreateJobDTO | ✅ |
| VO | `{Entity}VO` | JobVO | ✅ |
| Entity | `@TableName("rx_{table}")` | SysUser | ✅ |

### 4.3 异常处理（✅ 良好）

| 层级 | 处理方式 | 评价 |
|------|---------|------|
| Controller | GlobalExceptionHandler 统一捕获 | ✅ |
| Service | BusinessException 抛出 | ✅ |
| AS400 操作 | try-catch + log.warn | ⚠️ 部分吞异常 |
| 数据库 | DataAccessException 转友好提示 | ✅ |

**遗留问题：**
- 106 处 catch Exception，其中部分是合理的（AS400 连接失败降级），部分是「不想处理就吞掉」
- Service 层缺少统一的异常传播策略（部分方法 catch 后返回空结果，部分向上抛）

### 4.4 事务管理（✅ 零容忍架构）

- 全库 0 处 @Transactional
- 门禁脚本 `check-transactional.sh` 零容忍
- 理由：MySQL InnoDB 单语句原子 + AS400 只读，事务无收益

**风险：** 多步写操作（如用户创建 + 角色绑定）无原子性保证，失败时可能数据不一致。当前靠业务逻辑兜底（先创建用户再绑定角色），但缺少补偿机制。

### 4.5 缓存策略

| 缓存 | 实现 | TTL | 评价 |
|------|------|-----|------|
| 权限缓存 | Caffeine | 60s | ✅ 合理 |
| 登录用户信息 | 无 | - | ⚠️ 每次查库 |
| 菜单树 | 无 | - | ⚠️ 每次查库 |
| AS400 连接 | 连接池 | - | ✅ |
| 监控指标 | 无 | - | ⚠️ 仅数据库查询 |

**建议：** 菜单树变更频率极低（管理员偶尔调整），建议加 Caffeine 缓存（TTL 5 分钟），减少每次请求的 DB 查询。

### 4.6 LambdaQueryWrapper 使用（⚠️ 可优化）

当前 146 处 `new LambdaQueryWrapper<T>()`，虽然分层规范保证仅在 Service 层使用，但写法冗长。

**建议：** 统一改为 `Wrappers.<T>lambdaQuery()` 静态工厂，或 Service 继承 ServiceImpl 使用 `lambdaQuery()` 链式方法。
