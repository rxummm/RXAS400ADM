## 二、核心亮点（值得保持）

### 2.1 前端 `useTablePage` composable
43 处复用，统一了分页、缓存、前端模糊搜索、乐观更新、表格高度自适应——这是前端最大的架构资产。

### 2.2 8 道静态门禁
`verify-all.sh` 聚合分层/插槽/拼行/V38/迁移/事务/模板class/i18n，本地 pre-commit + CI 双保险。80 个 vitest 测试覆盖门禁脚本自身回归。

### 2.3 Token 混淆存储
`useStorage` 的 XOR 混淆虽然不防逆向，但比明文 localStorage 好一层，兼顾了简洁与安全。

### 2.4 多 AS400 服务器抽象
`AS400Client` 接口 + Mock/JTOpen 双实现 + ThreadLocal 上下文 + X-AS400-Server 头路由，架构优雅。

### 2.5 @OperateLog AOP 审计
118 处写操作全覆盖，审计日志自动落库到 `rx_audit_log`。

### 2.6 i18n 国际化
全站中英文双语（zh-CN / en-US），无硬编码中文，Element Plus 组件语言随 i18n 实时切换（P2-27）。

## 三、发现的问题与优化方案

### 🔴 P0 — 性能问题（影响用户体验）

#### 3.1 前端 JS Bundle 严重超标

**现状**：构建产物存在三个超大 chunk：

| Chunk | 原始大小 | Gzip 后 | 根因 |
|-------|----------|---------|------|
| `index-B0K1E421.js` | 1,609 KB | 522 KB | Element Plus 全量引入 + 全量图标注册 |
| `index-CDG_A0JD.js` | 968 KB | 332 KB | 依赖库合并 |
| `echarts-KdE5SxhG.js` | 544 KB | 182 KB | ECharts 全量引入 |

**根因分析**：
1. `main.ts` 中 `import * as ElementPlusIconsVue from '@element-plus/icons-vue'` + 循环注册所有图标（~400+ 图标全量打包）
2. `app.use(ElementPlus)` 全量引入 Element Plus（未做按需加载）
3. ECharts 未使用 `echarts/core` 按需引入（`dashboard/index.vue`、`monitor/` 等页面仅用了少量图表类型）

**推荐方案**：
- Element Plus：改用 `unplugin-vue-components` + `unplugin-auto-import` 实现自动按需导入
- ECharts：使用 `echarts/core` + `renderers: CanvasRenderer` + 按需注册 `BarChart`, `LineChart` 等
- 图标：改用 `unplugin-icons` 或手动按需 `import { xxx } from '@element-plus/icons-vue'`

**预期效果**：Bundle 从 ~2.5MB 降至 ~800KB，首屏加载时间显著降低。

#### 3.2 路由全量注册无异步降级

`router/index.ts` 已用 `() => import(...)` 做了懒加载 ✅，但 40+ 个路由在用户登录时全部预解析（router guard 中 `router.getRoutes()` 遍历）。对于未授权用户，这仍然会触发大量 chunk 解析。

**推荐方案**：对 system/monitor/report 等管理模块加 `defineAsyncComponent` + loading/error 降级。

### 🟡 P1 — 架构改进

#### 3.3 `useTablePage` 的 `resizeObserver` 全局选择器泄漏

```typescript
function bindResize() {
  nextTick(() => {
    const el = document.querySelector('.table-wrapper')  // ← 全局选择器
    resizeObserver = new ResizeObserver(...)
```

使用 `document.querySelector('.table-wrapper')` 做全局查找，如果页面同时存在多个 `.table-wrapper`（如抽屉/弹窗内也有表格），`ResizeObserver` 会绑定到错误元素。

**推荐方案**：改为通过 `ref` 或 `inject` 传递目标元素。

#### 3.4 `@Autowired` 字段注入残留 3 处

`ScheduleQuartzJob.java`、`ReportScheduleQuartzJob.java` 仍用 `@Autowired` 字段注入（Quartz Job 不支持构造器注入的已知限制）。注释已说明原因，属于技术债而非 bug。

#### 3.5 `request.ts` 的 `noDedupe` 标记缺乏类型安全保障

`RequestConfig extends AxiosRequestConfig` 中加了 `noDedupe?: boolean`，但调用方传入时需要 `as RequestConfig` 断言。建议封装一个 `createRequestConfig()` 工厂函数。

### 🟢 P2 — 代码质量

#### 3.6 LambdaQueryWrapper 在 Service 层使用 111 处

虽然分层规范已保证 Controller 不使用 QueryWrapper（✅），但 Service 层大量 `new LambdaQueryWrapper<>()` 仍存在构造冗余。MyBatis Plus 3.5.7 支持 `Wrappers.lambdaQuery()` 静态工厂方法，可减少样板代码。

#### 3.7 i18n key 全量加载

`frontend/src/i18n/index.ts` 用 `import messages from './lang/zh-CN'` 整体导入——这意味着所有 i18n key 在启动时全量加载。已有 `dynamic.ts` 动态加载机制，但似乎未完全利用。

#### 3.8 Flyway 迁移文件数量

迁移文件已到 V48+，每次启动 Flyway 校验耗时增加。`validate-on-migrate: false` 已关闭校验（✅），但可考虑定期执行 `mvn flyway:repair` 清理。
