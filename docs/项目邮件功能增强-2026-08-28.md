> 本文档是 `项目前后端增强-2026-08-27.md` §十五 的独立展开，详细记录邮件功能的分析、设计与实现。

## 一、当前邮件架构

### 1.1 核心组件

| 组件 | 模块 | 职责 |
|------|------|------|
| `EmailNotifier` | app | 唯一邮件发送类，SMTP 配置从 `rx_config` 数据库表动态读取 |
| `AlertWebhookListener` | app | 监听 `AlertRaisedEvent`，按 channel 分发（Webhook/邮件/站内通知） |
| `ReportScheduleService` | app | 报表定时推送，直接调用 `EmailNotifier.sendAttachment()` |

### 1.2 两个邮件使用场景

| 场景 | 触发方式 | 收件人来源 | 内容类型 | 附件 |
|------|---------|-----------|---------|------|
| 告警通知 | `AlertRaisedEvent` → `AlertWebhookListener` | 全局 `alert.email.to`（sys_config） | 纯文本 | 无 |
| 报表推送 | Quartz/手动 → `ReportScheduleService` | 每个任务的 `recipients` 字段（rx_report_schedule） | 纯文本 | PDF/Excel |

### 1.3 SMTP 配置（数据库驱动）

所有 SMTP 设置存储在 `rx_config` 表，通过通用系统参数页面管理：

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `alert.email.host` | `""`（空=禁用） | SMTP 服务器 |
| `alert.email.port` | `465` | 端口 |
| `alert.email.user` | `""` | 用户名 |
| `alert.email.pass` | `""` | 密码（自动脱敏） |
| `alert.email.from` | 回退到 user | 发件人地址 |
| `alert.email.to` | `""` | 告警收件人（全局） |

### 1.4 项目自身 vs AS400 — 无架构分离

AS400 模块零邮件代码——仅通过 `AlertRaisedEvent` 发布告警事件，app 模块的 `AlertWebhookListener` 统一处理。架构已是解耦设计。

## 二、当前缺失分析

| 缺失项 | 影响 | 优先级 |
|--------|------|--------|
| 无专用邮件配置 UI | 管理员需在通用参数页手动输入 `alert.email.*` 键值对 | P2 |
| 告警收件人全局单一 | 无法按告警规则/严重级别分组发送 | P2 |
| AS400 渠道不可配置 | 作业失败硬编码 `channel=ALL` | P3 |
| 无邮件重要性/优先级 | 所有邮件同等对待 | P3 |
| 无邮件发送历史/日志 | 发送成功/失败仅在应用日志中 | P3 |
| 无 HTML 邮件模板 | 所有邮件纯文本 | P3 |
| 无邮件队列/重试 | 发送失败仅记录日志 | P3 |
| 用户邮箱未作为发送目标 | `rx_user.email` 存在但从未用于发送 | P2 |

## 三、数据库设计

### 3.1 rx_email_config（邮件配置）

```sql
CREATE TABLE IF NOT EXISTS rx_email_config (
    config_key   VARCHAR(100)  NOT NULL PRIMARY KEY COMMENT '配置键（如 smtp.host）',
    config_value TEXT          NULL     COMMENT '配置值',
    description  VARCHAR(255)  NULL     COMMENT '描述',
    updated_time DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='邮件服务配置';
```

### 3.2 rx_email_recipient_group（收件人分组）

```sql
CREATE TABLE IF NOT EXISTS rx_email_recipient_group (
    id          BIGINT        NOT NULL AUTO_INCREMENT,
    group_name  VARCHAR(100)  NOT NULL COMMENT '分组名称',
    description VARCHAR(255)  NULL     COMMENT '描述',
    created_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_group_name (group_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='邮件收件人分组';
```

### 3.3 rx_email_recipient（分组成员）

```sql
CREATE TABLE IF NOT EXISTS rx_email_recipient (
    id         BIGINT        NOT NULL AUTO_INCREMENT,
    group_id   BIGINT        NOT NULL COMMENT '所属分组',
    email      VARCHAR(100)  NOT NULL COMMENT '邮箱地址',
    user_id    BIGINT        NULL     COMMENT '关联用户ID（可选）',
    enabled    TINYINT       NOT NULL DEFAULT 1 COMMENT '1=启用 0=禁用',
    created_time DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_group_id (group_id),
    UNIQUE KEY uk_group_email (group_id, email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='邮件分组成员';
```

### 3.4 rx_email_log（发送日志）

```sql
CREATE TABLE IF NOT EXISTS rx_email_log (
    id              BIGINT        NOT NULL AUTO_INCREMENT,
    subject         VARCHAR(255)  NOT NULL COMMENT '邮件主题',
    recipients      TEXT          NOT NULL COMMENT '收件人列表',
    channel         VARCHAR(20)   NOT NULL COMMENT '渠道：ALERT/REPORT/MANUAL',
    status          VARCHAR(20)   NOT NULL COMMENT '状态：SUCCESS/FAILED',
    error_message   TEXT          NULL     COMMENT '失败原因',
    attachment_name VARCHAR(255)  NULL     COMMENT '附件文件名',
    created_time    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_channel (channel),
    KEY idx_status (status),
    KEY idx_created_time (created_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='邮件发送日志';
```

### 3.5 数据迁移（rx_config → rx_email_config）

```sql
INSERT IGNORE INTO rx_email_config (config_key, config_value, description)
SELECT REPLACE(config_key, 'alert.email.', ''), config_value, description
FROM rx_config WHERE config_key LIKE 'alert.email.%';
```

### 7.2 配置化分析：`DEFAULT_SMTP_PORT` vs `DEFAULT_SMTP_TIMEOUT`

用户质疑：将 `"465"` / `"5000"` 提取为 Java 常量是否依然算"硬编码"？

**分析结论：**

| 常量 | 是否可 DB 配置 | 结论 |
|------|---------------|------|
| `DEFAULT_SMTP_PORT = "465"` | ✅ 已通过 `getConfig("port", DEFAULT_SMTP_PORT)` 可配置 | 常量仅作为兜底默认值，合理 |
| `DEFAULT_SMTP_TIMEOUT = "5000"` | ❌ 之前仅 `props.put(..., SMTP_TIMEOUT_MS)` | **已修复**：改为 `getConfig("timeout", DEFAULT_SMTP_TIMEOUT)` |

**数据流：**
```
前端 emailConfig 页面 → updateEmailConfigs({ timeout: "8000" })
  → rx_email_config 表（config_key='timeout', config_value='8000'）
  → EmailService.getConfig("timeout", "5000") → "8000"
  → props.put("mail.smtp.connectiontimeout", "8000")
  → props.put("mail.smtp.timeout", "8000")
```
