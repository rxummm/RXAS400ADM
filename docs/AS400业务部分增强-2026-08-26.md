## 一、背景：什么是 BPCS / Infor LX

| 维度 | 说明 |
|---|---|
| 定位 | Business Planning and Control System，SSA 公司 80 年代推出的制造业 ERP；SSA 被 Infor 收购后演进为 **Infor LX** |
| 平台 | IBM i (AS/400) 原生，语言为 RPG/AS-SET/COBOL + DB2 for i 物理文件 |
| 模块 | MRP、多地点库存、成本、财务（GL/AR/AP）、客户订单管理（COM）、采购、车间作业（SFC）、发票（BIL）、运输（OLM）等 |
| 现状 | 大量跨国制造企业仍在生产运行其财务/库存/订单模块——正是本项目目标客户群的核心场景 |

**对本项目的意义**：当前 AS400 业务部分偏"系统运维"（作业/子系统/IFS/系统值），
缺少面向业务的 ERP 数据可视化能力。接入 BPCS 订单/客户/库存等只读视图，
可让平台从「管机器」升级为「管机器 + 看业务」，价值显著。

## 二、调研结论：核心文件族与键结构

### 2.1 文件族总览（Customer Order / Inventory / Customer / Invoice / Shipping）

| 域 | 物理文件 | 含义 | 主要键/关系 |
|---|---|---|---|
| **订单** | **ECH** | Customer Order Header 客户订单头 | CONO + ORNO（公司+订单号） |
| | **ECL** | Customer Order Regular Lines 订单常规行 | CONO + ORNO + ORLN(行号)；ECH : ECL = 1 : N |
| | ECS | Customer Order Special Lines 特殊行（费用/文本行） | 同上 |
| | ELA | Allocations 行分配明细（数量→仓库→库位） | 关联 ECL 行 |
| | ESN | Customer Notes 订单备注 | — |
| | ECG | Customer Order Change History 订单变更历史 | 时间轴的"变更事件"补充源 |
| **发运** | ESH / ESL | Shipping Header / Detail 发运头/明细 | 关联订单 |
| **客户** | RCM | Customer Master 客户主档（Bill-To） | CONO + CUST(客户号) |
| | EST | Customer Ship-To 客户收货点 | CONO + CUST + SHIP |
| **库存** | IIM | Item Master 物料主档 | ITEM |
| | IWI / IWM | Warehouse × Item 库存量 / 主档 | WH + ITEM |
| | ILI / ILM | Warehouse × Item × Location × Lot 库存 / 主档 | WH + ITEM + LOC(+LOT) |
| | ITE | Inventory Transaction Effects 事务效果量 | WH + ITEM |
| | ITH | Inventory History 库存历史流水（⚠️ 超大文件） | — |
| **发票** | BBH / BBL | 活动 Invoice Header / Lines（在制） | BHDOCN 单据号；BLSTS3=待发运确认、BLSTS4=待开票 |
| | SIH / SIL | Invoice History 开票历史（一票一头/一行一行） | INVNO |
| **销售历史** | SSH / SSD | Sales History Header / Detail | — |
| **运输 Load** | LLH / LLM / LLX | Load Header / Mixed / …（OLM 载荷） | LHNO；LHSTAT=3 表示已 Dispatch |
| **采购**（远期） | HPO / HPH | Purchase Orders 头/明细 | PONO |

### 2.2 订单状态体系（★ 本设计的核心依据）

BPCS V6+ 的订单进度**不是单一状态字段**，而是五组 0/1 标志位：

| # | 标志位 | 阶段（英文） | 阶段（中文） | 典型触发程序 |
|---|---|---|---|---|
| 1 | ECH.CHSTS1 / ECL.CLSTS1 | **Pick Release** | 拣货释放 | ORD550 |
| 2 | CHSTS2 / CLSTS2 | **Pick Confirm** | 拣货确认 | ORD570 |
| 3 | CHSTS3 / CLSTS3 | **Ship Release** | 发运释放 | — |
| 4 | CHSTS4 / CLSTS4 | **Ship Confirm** | 发运确认 | ORD590 |
| 5 | CHSTS5 / CLSTS5 | **Billing** | 开票 | BIL500 |

关键语义（来自 BPCS-L 社区与 COM 手册 p112）：

- 标志位表示「**该行/该头下一步已完成的环节**」，取值 0 或 1；
- **头与行各自独立**：例——行 1 已发货开票、行 2 仅拣货释放时，
  `ECH.CHSTS = 10001`、`ECL1.CLSTS = 00001`、`ECL2.CLSTS = 10000`；
- 旧版单字符字段 `ECH.HSTAT` / `ECL.LSTAT`（E=Entered、F=Picked、7=部分开票、8=开票完…）
  在 V6 中**不再可靠维护**，仅作兼容参考；
- 记录标识：`ECH.HID='CH'`(在册) / `'CZ'`(已关闭归档)；`ECL.LID` 类似；
- 冻结体系（Hold）独立于上述流程：customer / credit / user / margin / credit-card hold
  （查询程序 ORD380），需在 UI 上作为**警示修饰**而非流程节点；
- 使用中标志：`ECH.HINUSE` 应为空——可作为「记录被锁定」的提示；
- 日期字段：BPCS 传统上使用 **CYYMMDD 7 位数字日期**（世纪+年月日），前端展示必须做转换。

> 设计决策 D1：**以 CHSTS1~5 / CLSTS1~5 为主状态源，HSTAT/LSTAT 仅作兜底显示**，
> 不参与时间轴推导（避免旧脏数据误导）。

## 三、与现有平台的集成分析

### 3.1 可直接复用的既有能力（零成本）

| 平台能力 | 位置 | 对本需求的复用方式 |
|---|---|---|
| 多服务器路由 | `X-AS400-Server` 头 → As400ServerContextHolder → AS400ClientProvider | 天然支持"选择哪台 BPCS 分区查询"；多公司/多分区场景免改造 |
| 只读 SQL 执行 | `SqlReadOnlyValidator` + `queryListCheckedBounded(sql, maxRows)` | 所有 BPCS 查询强制 SELECT/WITH 白名单 + `setMaxRows` 服务端截断，防大表拖垮 JVM |
| Mock 演示模式 | `MockSqlClient` 按 SQL 关键字路由仿真数据 | mock 档下新页面自动可用，无需真机即可开发联调 |
| 通用表浏览 | business 模块 `BusinessService.data(lib, tbl, page)` | 作为 P2 的"任意 BPCS 表兜底浏览器"底座 |
| 前端规范 | page-container--fit / search-bar / useSmartQueryTable / AppPagination / el-drawer 详情 | 新页面严格套用，保持全站一致 |
| 权限与菜单 | @PreAuthorize 权限码 + rx_menu 动态菜单 + v-has-perm | 新增权限码走标准 V{n} 种子迁移 |
| i18n | zh-CN / en-US 对称 + check:i18n 门禁 | 状态码描述全部 key 化 |

### 3.2 需要新增/决策的点

| # | 决策点 | 建议 |
|---|---|---|
| D1 | 状态源 | 以 CHSTS1~5/CLSTS1~5 位图为主，HSTAT/LSTAT 兼容显示（见 §2.2 决策 D1） |
| D2 | BPCS 库名 | 目标环境的 BPCS 文件所在 Library（常见 `BPCSF`/`SST901` 等各不相同）→ **配置化**：
  方案 a：yml `rxas400.bpcs.library`；方案 b（推荐）：rx_config 键 `bpcs.library`，系统配置页可改，随分区生效 |
| D3 | 公司码 CONO | BPCS 支持多公司。订单查询界面提供公司下拉；候选值来源：a) 启动后缓存 `SELECT DISTINCT CONO FROM ECH`（限流+TTL）；
  b) rx_config 手工维护逗号串。推荐 b 起步、a 为后续增强 |
| D4 | 日期转换 | CYYMMDD 数字 → ISO 日期：Java 端工具方法统一转换（`BpcsDateUtil.toLocalDate(Integer)`），
  SQL 内不做转换（保持谓词可走索引；排序按数字本身即自然序） |
| D5 | 只读边界 | 本期**纯查询零写操作**：不提供改价/解锁/重发布等功能，杜绝误操作 ERP 生产数据的合规风险 |
| D6 | 性能护栏 | 全部查询走 `queryListCheckedBounded(sql, ≤500)`；订单行查询必须带 `WHERE CONO=? AND ORNO=?` 谓词；
  严禁无谓词扫 ECH/ECL/ITH |
| D7 | 中文 CCSID | BPCS 文件若为 CCSID 65535（十六进制）会出现中文乱码——连接串追加 `;naming=system;data compression=true`
  并在连接属性中设置 `translate binary=true;ccsid=1399`（以环境实测为准，列入 §10 开放问题） |

#### 4.1.2 时间轴节点推导算法（后端聚合，前端零逻辑）

输入：ECH 行的 CHSTS1~5（'0'/'1'）+ Hold 相关字段 + 日期字段；
输出：固定 7 节点的有序数组（前端直接渲染，不做二次判断）：

| stageKey | 节点名 | reached 判定 | timestamp 来源（存在才填） |
|---|---|---|---|
| CREATED | 订单录入 | 恒 true | ENTDT/ENTTM（录入日期时间，字段名以 DDL 为准） |
| PICK_RELEASED | 拣货释放 | CHSTS1='1' | 无原生时间戳 → 仅标记达成（显示 ✓ 无时间） |
| PICK_CONFIRMED | 拣货确认 | CHSTS2='1' | 同上 |
| SHIP_RELEASED | 发运释放 | CHSTS3='1' | 同上 |
| SHIP_CONFIRMED | 发运确认 | CHSTS4='1' | ESH/LLH 关联日期（可选增强） |
| BILLED | 开票 | CHSTS5='1' | SIH 首张发票日期（可选增强） |
| CLOSED | 关闭归档 | HID='CZ' | PURGE 日期（可选） |

- `currentStageIndex` = 最后一个 reached 节点下标；前端据此高亮；
- **Hold 修正**：任一 Hold 字段非空 → 数组头部插入
  `{stageKey:'HOLD', level:'warning', holds:[{type:'credit',desc:…}]}` 警示节点（不改变 reached 序列）；
- 行级时间轴（抽屉内迷你条）：同算法换用 CLSTS1~5。

> 设计取舍说明：BPCS 原生不保存各阶段完成时刻（只有标志位），因此时间轴默认是
> 「里程碑达成态」而非「精确时刻线」。若客户环境存在 ECG 变更历史或自建审计表，
> 可在 P2+ 增强"真实时刻填充"，接口结构无需变化（timestamp 由 null → 有值）。

#### 4.1.4 SQL 草案（示意，字段名以环境 DDL 校正）

```sql
-- 头（含状态位原样取出，推导在 Java 完成，便于 mock 与单元测试）
SELECT CONO, ORNO, CUST, SHIP, HID, HSTAT,
       CHSTS1, CHSTS2, CHSTS3, CHSTS4, CHSTS5,
       ENTDT, REQDT, HINUSE
  FROM BPCSF.ECH
 WHERE CONO = ? AND ORNO = ?
FETCH FIRST 1 ROWS ONLY;

-- 行（分页）
SELECT ORLN, ITEM, WH, QTORD, QTSHP, QTINV, PRICE, DISC, CLSTS1…CLSTS5, LSTAT
  FROM BPCSF.ECL
 WHERE CONO = ? AND ORNO = ?
 ORDER BY ORLN
OFFSET ? ROWS FETCH NEXT ? ROWS ONLY;

-- 行计数
SELECT COUNT(*) FROM BPCSF.ECL WHERE CONO = ? AND ORNO = ?;
```

- 库名 `BPCSF` 来自 §3.2-D2 配置（拼接前经 `requireIdentifier` 白名单校验——复用 S6 成果）；
- 参数全部 `?` 占位符绑定（复用 SqlReadOnlyValidator + P1-6 占位符纪律）。

### 4.3 展示形态设计准则（保证"多种呈现"而非千篇一律的表格）

| 场景 | 推荐形态 | 组件 |
|---|---|---|
| 流程进度类（订单/退货） | 垂直时间轴 + 达成态圆点 + Hold 警示节点 | el-timeline |
| 主档类（客户/物料） | 卡片 + 描述列表 + 关联对象跳转 | el-descriptions + el-drawer |

## 九、风险与缓解

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 目标环境字段名/状态位与社区资料不一致 | 上线前 DDL 核对清单（§10①②）；SQL 集中在单一 Impl 便于一处调整 |
| 2 | ECH/ECL 无索引组合导致慢查 | 查询必带 CONO+ORNO 谓词；setMaxRows 下推；必要时建议客户建索引（运维建议而非代码） |
| 3 | 中文乱码（CCSID 65535） | 连接属性 translate binary/ccsid=1399 实验（§10⑤）；乱码字段降级为 hex 预览并标注 |
| 4 | 只读承诺被绕过的合规风险 | SqlReadOnlyValidator 强制 + 专用低权限 DB 用户（风险评估 §5.6 已要求）双重保险 |
| 5 | mock 数据与真机形状漂移 | mock 行集字段名与 SQL 别名一一对应，纳入 code review 检查项 |
| 6 | 大订单（数百行）前端卡顿 | lines 服务端分页（默认 20/页，AppPagination）；抽屉单行直查不走全量 |
