## 一、核心前提

本文档基于以下最终部署目标重新评估架构：

1. RXAS400ADM 最终直接部署到 IBM i / AS400
2. 不再使用 MySQL，数据最终使用 IBM i 上的 DB2 for i
3. IBM i 同时作为应用运行平台和被管理平台
4. 项目决定不采用 Spring `@Transactional` 作为核心业务一致性机制

**评估**：如果部署目标确实是「IBM i 既是应用宿主又是被管对象」，则以下所有设计推理成立。若仍保留 MySQL（混合架构），则部分设计可简化但方向不变。

---

## 二、架构重新定义

原架构：`Vue → Spring Boot → MySQL → JT400 → IBM i`（远程管理）

新架构：应用运行在 IBM i 本地，通过 JT400/JDBC/CL/IFS 直接操作系统资源。

**评估**：✅ 合理。这改变了「远程系统一致性」的性质——DB2 操作和 CL 命令虽然在同一台机器，但仍属于不同类型的操作，不天然组成一个业务事务。

---

## 三、核心命题：不使用事务 ≠ 不需要一致性设计

> 「不使用 Transaction Management，只代表不依靠数据库事务解决跨步骤业务一致性；并不代表可以忽略一致性。」

应采用：

```
State Machine    → 业务过程控制中心
Operation Log    → 记录每一步
Idempotency      → 防止重复执行
Retry            → 处理临时失败
Compensation     → 处理不可恢复失败
```

**评估**：✅ **非常合理**。这是对「禁止 @Transactional」策略的最佳补充。事务管理解决的是原子性，状态机解决的是过程一致性——两者解决不同维度的问题。对于 IBM i 管理平台，状态机比事务更贴合实际需求。

---

## 四、状态机设计：State + Step 模型

核心思想：不仅记录 `status`，还记录 `current_step`。

建议的 RX_OPERATION 表字段：

| 字段 | 用途 |
|------|------|
| `operation_id` | 操作唯一标识 |
| `operation_type` | 操作类型（CREATE_USER / END_JOB / ...） |
| `status` | REQUESTED / RUNNING / SUCCESS / FAILED / ... |
| `current_step` | 当前执行到哪一步 |
| `target` | 操作目标（用户/作业/文件名） |
| `request_data` | 请求参数 |
| `result_data` | 结果数据 |
| `error_code` / `error_message` | 错误信息 |
| `retry_count` / `max_retry` | 重试控制 |
| `idempotency_key` | 幂等键 |

配合 RX_OPERATION_STEP 表记录每步的执行状态。

**评估**：✅ **设计优秀**。这比单纯 `status = FAILED` 强很多——管理员可以看到「Create User ✔ / Set Group ✔ / Set Authority ✘ / Complete ○」，运维体验极佳。

---

## 五、统一状态定义

```
REQUESTED → RUNNING → STEP_SUCCESS → NEXT_STEP → COMPLETED
                  ↓
                FAILED
                  ↓
              RETRYING → RUNNING
                  ↓
         PARTIAL_SUCCESS / CANCELLED
```

**评估**：✅ 合理。状态定义清晰，转换路径合法，禁止 `FAILED → SUCCESS` 等非法跳转。

---

## 六、Retry 从失败步骤继续（不重跑已成功步骤）

这是状态机最大的价值之一。

如果 `CRTUSRPRF` 成功但 `GRPUSRPRF` 失败，Retry 只执行 `SET_GROUP`，不重新创建用户。

**评估**：✅ **极其重要**。IBM i 操作很多不是天然幂等的（CRTUSRPRF 重复执行会报 CPF），状态机的 step-level retry 是正确方案。

---

## 七、幂等性设计

每个 Operation 必须有 `IDEMPOTENCY_KEY`，防止前端重复提交导致重复执行。

对无法天然幂等的 IBM i 操作（如 CRTUSRPRF），需要 Before Check：

```
IF user exists → verify desired state → 认为 STEP SUCCESS
ELSE → create
```

**评估**：✅ 合理。管理员操作经常遇到浏览器 timeout 后重试，没有幂等性会导致严重问题。

---

## 八、Verify 模式：Execute → Query → Compare

不能认为 `client.execute(command)` 没抛异常就一定完成。

正确方式：

```
Execute → Query IBM i → Compare desired state → SUCCESS / FAILED
```

**评估**：✅ **非常重要**。CL 命令的返回码不总能反映真实状态，query-based verification 是 IBM i 管理的最佳实践。

---

## 九、IBM i 执行边界统一设计

当前问题：安全策略分散在不同 Service/Client 中，容易出现「A API 安全，B API 忘记检查」。

建议统一为：

```
Controller → Application Service → Operation Policy → IBM i Gateway → JT400
```

Operation Policy 统一处理：Permission / Risk / Parameter Validation / Confirmation / Audit。

**评估**：✅ **合理且必要**。当前项目确实存在 AS400-010（SWITCHUSR 无校验）、AS400-011（DataArea library 无校验）等分散验证遗漏，统一 Gateway 是正确解法。

## 十、风险等级模型

| 等级 | 操作示例 | 要求 |
|------|----------|------|
| READ | JOB_LIST, USER_LIST, IFS_READ | Permission + Audit |
| WRITE | USER_CREATE, IFS_WRITE | Permission + Validation + Audit |
| DESTRUCTIVE | DELETE_SPOOL, END_JOB | Permission + Validation + Confirmation + Audit |
| CRITICAL | CHGSYSVAL, END_SUBSYSTEM_IMMED, *ALLOBJ | Special Permission + Confirmation + Reason + Audit |
| BREAK_GLASS | RAW_CL | Break-glass Permission + Explicit Confirmation + Reason + Audit + Command Policy |

**评估**：✅ 合理。5 级风险模型覆盖了 IBM i 管理的所有场景，特别是将 `*ALLOBJ` 等特殊权限提升到 CRITICAL 级别，与代码审查中发现的 AS400-015 问题直接对应。

---

## 十一、权限细化

当前 `USER_MANAGE` 过于宽泛，应拆分为：

```
USER_VIEW / USER_CREATE / USER_UPDATE / USER_DELETE
USER_AUTHORITY / USER_CRITICAL_AUTHORITY (SPCAUT)
```

**评估**：✅ 合理。当前一个 `USER_PROFILE_MANAGE` 权限就能提交 `*ALLOBJ`，这在生产环境是不可接受的。

---

## 十二、Raw CL = Break-glass 边界

```
Normal API → Typed Operation → Validation → Policy → JT400
Raw CL → BREAK_GLASS → Strong Permission → Confirmation → Reason → Audit → JT400
```

**评估**：✅ 合理。Raw CL 是最强能力，必须作为特殊边界处理。

---

## 十三、Blacklist 不是唯一安全边界

当前 `DangerousClCommandValidator` 仅做 blacklist，CALL QCMDEXC 可绕过。

建议：Allowlist + structured command parser + parameter validation。

**评估**：✅ 与代码审查发现（C-SEC-006）一致。Blacklist 作为第二道防线有价值，但不能是唯一防线。

---

## 十四、Desired State / Actual State 模型

```
Desired: User=ROBIN, Group=DEV, Status=ENABLED, Authority=*ALLOBJ
Actual:  Query IBM i → 对比
Drift:   差异检测 → Remediation
```

**评估**：✅ **非常适合 IBM i 管理平台**。这实际上可以发展成 IBM i Configuration Management 能力——自动检测配置漂移并修复。

## 十五、Compensation 设计

区分 `AUTO_COMPENSATABLE`（如临时目录可自动删除）和 `MANUAL_COMPENSATION`（如 User Profile 建议人工审核）。

**评估**：✅ 合理。自动补偿 User Profile 删除风险太高，人工审核是正确选择。

## 十九、深度分析：落地路径补充（2026-09-07）

> 以下 10 项为原附录 A 缺失的实施细节，经逐行对比代码库后补充。

### 19.1 迁移策略 — Strangler Fig 模式

当前 as400/service/ 下有 113 个 Service 实现，全部是「直接执行」模式：

```
Controller → Service → AS400Client.execute(command) → return result
```

一步到位重写所有 Service 风险极高。建议采用 **Strangler Fig（绞杀者模式）** 分三阶段迁移：

| 阶段 | 范围 | 策略 |
|------|------|------|
| Phase 0 | 新建 `rxas400adm-operation` 模块 | 仅搭建 Operation/Step/Policy/Gateway 基础设施，不改动现有 Service |
| Phase 1 | 高风险操作（User Profile / Job END / Subsystem END / RAW CL） | 逐个迁移到 Operation 模式，现有 Service 保持不变 |
| Phase 2 | 中风险操作（IFS / Document / Spool） | 批量迁移 |
| Phase 3 | 低风险只读操作（Job List / User List） | 保持直接执行，无需状态机 |

**关键点**：Phase 0 和 Phase 1 可以与现有代码并行运行，通过 Feature Flag 控制切换。

### 19.2 与现有 Audit 的关系定义

项目已有 `@OperateLog` 注解（AOP 自动写 `rx_audit_log`），但它是 HTTP 层面的审计，只记录「谁调了哪个 API」。

需要明确 **两层审计** 的职责边界：

| 层级 | 表 | 记录内容 | 触发时机 |
|------|-----|---------|---------|
| HTTP Audit | `rx_audit_log`（现有） | 谁、什么时间、调了哪个 API、IP、参数 | `@OperateLog` AOP |
| Operation Audit | `rx_operation_step`（新增） | 每个 Step 的执行结果、耗时、IBM i 返回码 | Step Executor 执行后 |

两者通过 `operation_id` 关联。`rx_audit_log` 可以增加 `operation_id` 外键字段，实现从 API 调用追溯到具体 Operation Step。

### 19.3 并发安全设计 — CAS + Version

Operation 状态机本身的并发问题：两个管理员同时对同一个 User Profile 发起「修改权限」操作，可能产生冲突。

```sql
-- RX_OPERATION 增加版本字段
ALTER TABLE rx_operation ADD COLUMN version INT DEFAULT 1;

-- CAS 更新状态
UPDATE rx_operation 
SET status = 'RUNNING', version = version + 1 
WHERE id = ? AND version = ? AND status = 'REQUESTED';
-- 检查 affectedRows == 1，否则抛 CONFLICT
```

对于分布式部署（多实例），需要在 `IDEMPOTENCY_KEY` 上加 DB UNIQUE 约束，利用数据库的原子性保证幂等。

### 19.4 超时与清理机制

当前架构文档提到 RETRYING 状态和 max_retry，但没有定义：

- Operation 超时阈值（多久没完成算超时？）
- 超时后的清理策略（谁来触发？）
- 死任务检测（Running 状态但 Step 已经不推进了）

建议：

```java
// Operation 超时配置
public class OperationTimeoutConfig {
    private static final Map<OperationType, Duration> TIMEOUTS = Map.of(
        OperationType.CREATE_USER, Duration.ofMinutes(5),
        OperationType.END_JOB, Duration.ofMinutes(2),
        OperationType.IFS_WRITE, Duration.ofMinutes(10),
        OperationType.RAW_CL, Duration.ofMinutes(1)
    );
}

// 定时任务：扫描超时 Operation
@Scheduled(fixedRate = 60_000)
public void cleanupStuckOperations() {
    // 查找 status=RUNNING AND updated_at < now()-timeout 的 Operation
    // 标记为 FAILED，记录 error_code='OPERATION_TIMEOUT'
}
```

### 19.5 Gateway 熔断与降级策略

IBM i 网络中断或 JT400 连接池耗尽时，所有操作都会阻塞。需要 CircuitBreaker：

```java
@Component
public class IbmiGateway {
    
    private final CircuitBreaker circuitBreaker;
    
    public OperationResult execute(OperationContext ctx) {
        return circuitBreaker.executeSupplier(() -> {
            // 1. Policy 检查
            policyEngine.check(ctx);
            // 2. 执行
            return jtopenClient.execute(ctx);
        });
    }
}

// application.yml
rxas400.operation.circuit-breaker:
  failure-threshold: 5
  recovery-timeout: 30s
  fallback: REJECT_WITH_MESSAGE  // 或 DEGRADE_TO_READ_ONLY
```

### 19.6 Operation Type 注册机制 — 注解驱动

每新增一个 Operation 都要手动修改多处代码（枚举、Policy、Gateway），扩展性差。建议采用注解驱动 + 自动注册：

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface IbmiOperation {
    String code();           // e.g., "USER_CREATE"
    RiskLevel riskLevel();   // e.g., RiskLevel.WRITE
    String requiredPermission();  // e.g., "USER_CREATE"
}

// 使用
@IbmiOperation(code = "USER_CREATE", riskLevel = RiskLevel.WRITE, 
                requiredPermission = "USER_CREATE")
public class CreateUserExecutor implements OperationExecutor {
    // ...
}
```

通过 `ApplicationContext.getBeansWithAnnotation(IbmiOperation.class)` 自动注册到 `OperationRegistry`。

### 19.7 Desired State 存储与版本管理

Desired State 存在 Operation 表里，每次修改都创建新 Operation，历史 Desired State 会丢失。

建议新增 `rx_desired_state` 表：

```sql
CREATE TABLE rx_desired_state (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    target_type VARCHAR(50) NOT NULL,  -- 'USER_PROFILE', 'JOB_CONFIG', ...
    target_name VARCHAR(255) NOT NULL,  -- 'ROBIN', 'QBATCH', ...
    state_data JSON NOT NULL,           -- {"group":"DEV","status":"ENABLED","authorities":["*ALLOBJ"]}
    version INT DEFAULT 1,
    created_by VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_target (target_type, target_name)
);

-- Operation 执行后更新 Desired State
UPDATE rx_desired_state 
SET state_data = ?, version = version + 1 
WHERE target_type = ? AND target_name = ? AND version = ?;
```

这样可以实现 **配置漂移检测**：定期对比 Desired State 与 Actual State，发现 drift 自动告警或修复。

### 19.8 前端交互协议

后端状态机需要与前端交互，定义 REST API + WebSocket 推送协议：

```text

# 查询 Operation 状态
GET /api/v1/operations/{id}
```

### 19.9 Feature Flag 控制切换

Phase 0/1 迁移期间，新旧模式并行运行。建议通过配置开关控制：

```yaml
rxas400:
  operation:
    enabled: false  # Phase 0: 关闭；Phase 1: 逐步打开
    types:
      USER_CREATE: true   # Phase 1: 优先迁移
      END_JOB: true
      IFS_WRITE: false    # Phase 2: 后续迁移
```

Service 层通过 `@ConditionalOnProperty` 或运行时检查决定走 Operation 模式还是直接执行。

## 总体结论

> **架构设计本身优秀（9/10），落地路径已补充完毕。** 核心价值在于：
>
> 1. 将「禁止 @Transactional」从缺陷转化为架构特色——用状态机替代事务作为一致性机制
> 2. 统一了 IBM i 操作的安全边界（Policy + Gateway），解决了当前分散验证的问题
> 3. Verify 模式（Execute → Query → Compare）比简单检查返回码更可靠
> 4. Desired State / Actual State 模型为未来 Configuration Management 打下基础
> 5. 与代码审查发现的 8+ 个问题直接对应，提供系统性解决方案

### 实施路线

优先落地 5 个基础设施（不在当前修复清单中，作为独立架构增强）：

1. `RX_OPERATION` 表
2. `RX_OPERATION_STEP` 表
3. `OperationStateMachine` 引擎
4. `IbmiOperationPolicy` 策略框架
5. `IbmiGateway` 统一执行入口

然后逐步迁移：User Profile → Job → IFS/Document → Spool → Subsystem → System Value → Deployment。

### Step 0.4 — 状态机引擎

#### `OperationStateMachine.java`

```java
package com.rxas400adm.operation.service;

import com.rxas400adm.common.exception.BusinessException;
import com.rxas400adm.common.exception.ErrorCode;
import com.rxas400adm.operation.domain.Operation;
import com.rxas400adm.operation.domain.OperationStatus;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;

/**
 * 状态机引擎：校验转换合法性 + CAS 更新版本号。
 * 不使用 @Transactional，依赖单语句原子性。
 */
@Slf4j
@Component
public class OperationStateMachine {

    /**
     * CAS 推进状态（防并发冲突）。
     * @return true=推进成功；false=版本冲突（需重试或报 CONFLICT）
     */
    public boolean advance(Operation op, OperationStatus targetStatus) {
        if (!op.getStatus().equals(targetStatus.name())) {
            OperationStatus current = OperationStatus.valueOf(op.getStatus());
            if (!current.canTransitionTo(targetStatus)) {
                log.warn("非法状态转换: {} → {} (opId={})", op.getStatus(), targetStatus, op.getId());
                throw new BusinessException(ErrorCode.BAD_REQUEST,
                    "非法状态转换: " + op.getStatus() + " → " + targetStatus);
            }
        }
        // CAS 更新：version + status 同时检查
        int affected = operationMapper.casUpdateStatus(op.getId(), targetStatus.name(), op.getVersion());
        if (affected == 0) {
            log.warn("Operation CAS 冲突: id={}, currentVersion={}", op.getId(), op.getVersion());
            return false;
        }
        op.setStatus(targetStatus.name());
        op.setVersion(op.getVersion() + 1);
        return true;
    }

    /** 标记失败（记录错误信息） */
    public void markFailed(Operation op, String errorCode, String errorMessage) {
        operationMapper.updateStatus(op.getId(), OperationStatus.FAILED.name(),
            errorCode, errorMessage, op.getVersion());
        op.setStatus(OperationStatus.FAILED.name());
        op.setErrorCode(errorCode);
        op.setErrorMessage(errorMessage);
    }

    /** 标记重试（retry_count + 1） */
    public boolean markRetrying(Operation op) {
        if (op.getRetryCount() >= op.getMaxRetry()) {
            log.warn("Operation 达到最大重试次数: id={}, retry={}/{}", op.getId(), op.getRetryCount(), op.getMaxRetry());
            return false;
        }
        operationMapper.incrementRetry(op.getId());
        op.setRetryCount(op.getRetryCount() + 1);
        return true;
    }
}
```

### Step 0.6 — OperationService 编排层

#### `OperationService.java`

```java
package com.rxas400adm.operation.service;

import com.rxas400adm.common.exception.BusinessException;
import com.rxas400adm.common.exception.ErrorCode;
import com.rxas400adm.operation.domain.*;
import com.rxas400adm.operation.executor.OperationExecutor;
import com.rxas400adm.operation.executor.StepExecutor;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.context.ApplicationContext;
import org.springframework.stereotype.Service;

import java.time.LocalDateTime;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

/**
 * Operation 编排层：创建 → 启动 → 逐步执行 → 完成/失败/重试。
 * 不使用 @Transactional，每步独立提交。
 */
@Slf4j
@Service
@RequiredArgsConstructor
public class OperationService {

    private final OperationMapper operationMapper;
    private final OperationStepMapper stepMapper;
    private final OperationStateMachine stateMachine;
    private final ApplicationContext applicationContext;

    /** 运行时注册表：由 OperationRegistry 在启动时填充 */
    private final Map<String, OperationExecutor> executorRegistry = new ConcurrentHashMap<>();

    // ─── 创建 ────────────────────────────────────────────────

    public Operation get(Long id) {
        Operation op = operationMapper.selectById(id);
        if (op == null) {
            throw new BusinessException(ErrorCode.NOT_FOUND, "Operation 不存在: " + id);
        }
        return op;
    }

    public Operation create(String operationType, String targetType, String targetName,
                            String requestData, String idempotencyKey, String requestedBy) {
        // 幂等检查
        if (idempotencyKey != null) {
            Operation existing = operationMapper.selectByIdempotencyKey(idempotencyKey);
            if (existing != null) {
                log.info("幂等命中，返回已有 Operation: id={}, type={}", existing.getId(), operationType);
                return existing;
            }
        }

        // 风险等级从 Executor 注解获取
        OperationExecutor executor = getExecutor(operationType);
        RiskLevel riskLevel = resolveRiskLevel(operationType);

        Operation op = new Operation();
        op.setOperationType(operationType);
        op.setStatus(OperationStatus.REQUESTED.name());
        op.setTargetType(targetType);
        op.setTargetName(targetName);
        op.setRequestData(requestData);
        op.setIdempotencyKey(idempotencyKey);
        op.setRiskLevel(riskLevel.name());
        op.setRequestedBy(requestedBy);
        op.setRequestedAt(LocalDateTime.now());
        op.setRetryCount(0);
        op.setMaxRetry(3);
        op.setVersion(1);
        operationMapper.insert(op);

        // 创建 Step 记录（NOT_EXECUTED）
        List<String> steps = executor.defineSteps();
        for (int i = 0; i < steps.size(); i++) {
            OperationStep step = new OperationStep();
            step.setOperationId(op.getId());
            step.setStepCode(steps.get(i));
            step.setStepOrder(i + 1);
            step.setStatus("NOT_EXECUTED");
            step.setRetryCount(0);
            stepMapper.insert(step);
        }

        log.info("Operation 创建: id={}, type={}, target={}/{}", op.getId(), operationType, targetType, targetName);
        return op;
    }

    // ─── 执行 ────────────────────────────────────────────────

    public Operation execute(Long operationId) {
        Operation op = operationMapper.selectById(operationId);
        if (op == null) {
            throw new BusinessException(ErrorCode.NOT_FOUND, "Operation 不存在: " + operationId);
        }

        // CAS 推进到 RUNNING
        if (!stateMachine.advance(op, OperationStatus.RUNNING)) {
            throw new BusinessException(ErrorCode.CONFLICT, "Operation 状态冲突，请刷新后重试");
        }
        op.setStartedAt(LocalDateTime.now());
        operationMapper.updateStartedAt(op.getId(), op.getStartedAt());

        OperationExecutor executor = getExecutor(op.getOperationType());
        List<String> steps = executor.defineSteps();

        // 从 current_step 或第一个步骤开始（支持 Retry 从失败步骤继续）
        int startIndex = resolveStartIndex(op, steps);

        for (int i = startIndex; i < steps.size(); i++) {
            String stepCode = steps.get(i);
            op.setCurrentStep(stepCode);
            operationMapper.updateCurrentStep(op.getId(), stepCode);

            // 更新 Step 为 RUNNING
            stepMapper.updateStatus(op.getId(), stepCode, "RUNNING");

            long start = System.currentTimeMillis();
            StepResult result;
            try {
                result = executor.executeStep(op, stepCode);
                // Verify（如果定义了）
                StepResult verify = executor.verifyStep(op, stepCode);
                if (verify != null && verify.status() == StepResult.StepStatus.FAILED) {
                    result = verify;
                }
            } catch (Exception e) {
                result = StepResult.failed("EXCEPTION", e.getMessage(), e.getMessage(),
                    System.currentTimeMillis() - start);
            }

            long duration = System.currentTimeMillis() - start;
            stepMapper.updateResult(op.getId(), stepCode, result, duration);

            if (result.status() == StepResult.StepStatus.SUCCESS) {
                log.info("Step 成功: op={}, step={}, duration={}ms", op.getId(), stepCode, duration);
            } else {
                // Step 失败
                log.warn("Step 失败: op={}, step={}, error={}", op.getId(), stepCode, result.errorDetail());
                stateMachine.markFailed(op, "STEP_FAILED", "步骤 [" + stepCode + "] 失败: " + result.errorDetail());
                operationMapper.updateCompletedAt(op.getId(), LocalDateTime.now());

                // 尝试重试
                if (stateMachine.markRetrying(op)) {
                    log.info("Operation 进入重试: op={}, retry={}", op.getId(), op.getRetryCount());
                    // 跳出循环，等待下次 execute() 调用
                }
                return op;
            }
        }

        // 全部步骤成功
        stateMachine.advance(op, OperationStatus.SUCCESS);
        op.setCompletedAt(LocalDateTime.now());
        operationMapper.updateCompletedAt(op.getId(), op.getCompletedAt());
        log.info("Operation 完成: id={}, type={}, duration={}ms", op.getId(), op.getOperationType(),
            java.time.Duration.between(op.getStartedAt(), op.getCompletedAt()).toMillis());

        return op;
    }

    // ─── 重试 ────────────────────────────────────────────────

    public Operation retry(Long operationId) {
        Operation op = operationMapper.selectById(operationId);
        if (op == null) {
            throw new BusinessException(ErrorCode.NOT_FOUND, "Operation 不存在: " + operationId);
        }
        if (!OperationStatus.FAILED.name().equals(op.getStatus())
            && !OperationStatus.RETRYING.name().equals(op.getStatus())) {
            throw new BusinessException(ErrorCode.BAD_REQUEST, "只有 FAILED/RETRYING 状态可以重试");
        }
        return execute(operationId);
    }

    // ─── 取消 ────────────────────────────────────────────────

    public void cancel(Long operationId) {
        Operation op = operationMapper.selectById(operationId);
        if (op == null) {
            throw new BusinessException(ErrorCode.NOT_FOUND, "Operation 不存在: " + operationId);
        }
        stateMachine.advance(op, OperationStatus.CANCELLED);
        operationMapper.updateCompletedAt(op.getId(), LocalDateTime.now());
    }

    // ─── 内部方法 ────────────────────────────────────────────

    private OperationExecutor getExecutor(String operationType) {
        OperationExecutor executor = executorRegistry.get(operationType);
        if (executor == null) {
            throw new BusinessException(ErrorCode.BAD_REQUEST, "未知的 Operation 类型: " + operationType);
        }
        return executor;
    }

    private int resolveStartIndex(Operation op, List<String> steps) {
        if (op.getCurrentStep() == null) return 0;
        int idx = steps.indexOf(op.getCurrentStep());
        return idx >= 0 ? idx : 0;
    }

    private RiskLevel resolveRiskLevel(String operationType) {
        OperationExecutor executor = executorRegistry.get(operationType);
        if (executor == null) return RiskLevel.READ;
        IbmiOperation annotation = executor.getClass().getAnnotation(IbmiOperation.class);
        return annotation != null ? annotation.riskLevel() : RiskLevel.READ;
    }
}
```

```java
@Slf4j
```

```java
    private final RiskPolicy riskPolicy;

     * 执行前策略检查。
     * @param confirmationToken CRITICAL/BREAK_GLASS 操作需要的确认令牌
     */
    public void check(Operation op, String confirmationToken) {
        OperationExecutor executor = registry.get(op.getOperationType());
        if (executor == null) {
            throw new BusinessException(ErrorCode.BAD_REQUEST, "未知 Operation 类型: " + op.getOperationType());
        }

        IbmiOperation annotation = executor.getClass().getAnnotation(IbmiOperation.class);
        if (annotation == null) {
            throw new BusinessException(ErrorCode.INTERNAL_ERROR, "Operation 缺少 @IbmiOperation 注解");

        // 1. 权限检查
        if (!annotation.requiredPermission().isEmpty()) {
            riskPolicy.checkPermission(annotation.requiredPermission());
        }

        // 2. 风险等级检查
        riskPolicy.checkRiskLevel(annotation.riskLevel(), op);

        // 3. 确认检查（CRITICAL/BREAK_GLASS）
        confirmationPolicy.checkConfirmation(annotation.riskLevel(), confirmationToken);
    }
}
```

```java
@Component
public class RiskPolicy {

    public void checkPermission(String requiredPermission) {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        if (auth == null) {
            throw new BusinessException(ErrorCode.UNAUTHORIZED, "未登录");
        }
        boolean hasPermission = auth.getAuthorities().stream()
            .map(GrantedAuthority::getAuthority)
            .anyMatch(a -> a.equals(requiredPermission) || a.equals("ROLE_ADMIN"));
        if (!hasPermission) {
            throw new BusinessException(ErrorCode.FORBIDDEN, "权限不足: " + requiredPermission);
        }
    }

    public void checkRiskLevel(RiskLevel riskLevel, Operation op) {
        switch (riskLevel) {
            case CRITICAL -> {
                // 需要特殊权限 USER_CRITICAL_AUTHORITY
                checkPermission("USER_CRITICAL_AUTHORITY");
            }
            case BREAK_GLASS -> {
                // 需要 BREAK_GLASS 权限
                checkPermission("BREAK_GLASS_EXECUTE");
            }
            default -> { /* READ/WRITE/DESTRUCTIVE 无额外权限要求 */ }
        }
    }
}
```

```java
package com.rxas400adm.operation.gateway;

import com.rxas400adm.as400.AS400Client;
import com.rxas400adm.as400.AS400ClientProvider;
import com.rxas400adm.common.exception.BusinessException;
import com.rxas400adm.common.exception.ErrorCode;
import com.rxas400adm.operation.domain.Operation;
import com.rxas400adm.operation.policy.OperationPolicyEngine;
import io.github.resilience4j.circuitbreaker.annotation.CircuitBreaker;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;

/**
 * 统一执行入口：Policy 检查 → 熔断保护 → AS400Client 调用。
 * 所有 IBM i 操作必须经过此 Gateway。
 */
@Slf4j
@Component
@RequiredArgsConstructor
public class IbmiGateway {

    private final AS400ClientProvider clientProvider;
    private final OperationPolicyEngine policyEngine;

    /**
     * 带熔断保护的执行入口。
     * 熔断器配置：连续失败 5 次后快速失败，30s 后尝试恢复。
     */
    @CircuitBreaker(name = "ibmiGateway", fallbackMethod = "fallback")
    public <T> T execute(Operation op, java.util.function.Function<AS400Client, T> action, String confirmationToken) {
        // 1. Policy 检查
        policyEngine.check(op, confirmationToken);

        // 2. 获取当前服务器客户端
        AS400Client client = clientProvider.current();

        // 3. 执行
        log.info("Gateway 执行: op={}, type={}, target={}", op.getId(), op.getOperationType(), op.getTargetName());
        long start = System.currentTimeMillis();
        try {
            T result = action.apply(client);
            log.info("Gateway 执行成功: op={}, duration={}ms", op.getId(), System.currentTimeMillis() - start);
            return result;
        } catch (Exception e) {
            log.error("Gateway 执行失败: op={}, error={}", op.getId(), e.getMessage(), e);
            throw new BusinessException(ErrorCode.AS400_CONNECTION_FAILED,
                "IBM i 操作执行失败: " + e.getMessage());
        }
    }

    /** 熔断降级：IBM i 不可用时快速失败 */
    private <T> T fallback(Operation op, java.util.function.Function<AS400Client, T> action,
                           String confirmationToken, Throwable t) {
        log.error("IBM i 熔断触发，操作被拒绝: op={}, type={}", op.getId(), op.getOperationType());
        throw new BusinessException(ErrorCode.SERVICE_UNAVAILABLE,
            "IBM i 服务暂时不可用，请稍后重试（熔断保护）");
    }
}
```

```java
package com.rxas400adm.operation.timeout;

import com.rxas400adm.operation.domain.Operation;
import com.rxas400adm.operation.domain.OperationStatus;
import com.rxas400adm.operation.service.OperationMapper;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

import java.time.Duration;
import java.time.LocalDateTime;
import java.util.List;
import java.util.Map;

/**
 * 定时扫描超时/卡死的 Operation，标记为 FAILED。
 */
@Slf4j
@Component
@RequiredArgsConstructor
public class OperationTimeoutScheduler {

    private final OperationMapper operationMapper;

    /** 各 OperationType 超时阈值（分钟） */
    private static final Map<String, Duration> TIMEOUTS = Map.of(
        "USER_CREATE",    Duration.ofMinutes(5),
        "USER_UPDATE",    Duration.ofMinutes(3),
        "USER_DELETE",    Duration.ofMinutes(3),
        "END_JOB",        Duration.ofMinutes(2),
        "END_SUBSYSTEM",  Duration.ofMinutes(3),
        "IFS_WRITE",      Duration.ofMinutes(10),
        "IFS_DELETE",     Duration.ofMinutes(5),
        "RAW_CL",         Duration.ofMinutes(1),
        "SPOOL_DELETE",   Duration.ofMinutes(3)
    );

    private static final Duration DEFAULT_TIMEOUT = Duration.ofMinutes(5);

    @Scheduled(fixedRate = 60_000) // 每分钟扫描一次
    public void cleanupStuckOperations() {
        List<Operation> stuckOps = operationMapper.findStuckOperations(
            OperationStatus.RUNNING.name(), LocalDateTime.now()
        );

        for (Operation op : stuckOps) {
            Duration timeout = TIMEOUTS.getOrDefault(op.getOperationType(), DEFAULT_TIMEOUT);
            if (op.getStartedAt() != null && Duration.between(op.getStartedAt(), LocalDateTime.now()).compareTo(timeout) > 0) {
                log.warn("Operation 超时: id={}, type={}, started={}, timeout={}",
                    op.getId(), op.getOperationType(), op.getStartedAt(), timeout);
                operationMapper.markFailed(op.getId(), "OPERATION_TIMEOUT",
                    "操作超时（阈值 " + timeout.toMinutes() + " 分钟）", op.getVersion());
            }
        }
    }
}
```

```java
                // Before Check（幂等）：如果用户已存在，检查是否符合 Desired State
                var existing = client.queryList(
                    "SELECT USER_PROFILE_NAME FROM TABLE(QSYS2.USER_INFO('" + userName + "')) X");
                if (!existing.isEmpty()) {
                    yield StepResult.success("CPF2217", "用户已存在，视为成功", System.currentTimeMillis() - start);
                }
                String cmd = "CRTUSRPRF USRPRF(" + userName + ") PASSWORD(*NONE) STATUS(*ENABLED)";
                String result = client.execute(cmd);
                yield StepResult.success(result, "用户创建成功", System.currentTimeMillis() - start);
            }
            case "SET_GROUP" -> {
                String userName = extractTargetName(op);
                String group = extractGroup(op);
                if (group == null || group.isBlank()) {
                    yield StepResult.success("N/A", "未指定组，跳过", System.currentTimeMillis() - start);
                }
                String cmd = "CHGUSRPRF USRPRF(" + userName + ") GRPPRF(" + group + ")";
                String result = client.execute(cmd);
                yield StepResult.success(result, "组设置成功", System.currentTimeMillis() - start);
            }
            case "SET_AUTHORITY" -> {
                String userName = extractTargetName(op);
                String authority = extractAuthority(op);
                if (authority == null || authority.isBlank()) {
                    yield StepResult.success("N/A", "未指定权限，跳过", System.currentTimeMillis() - start);
                }
                String cmd = "CHGUSRPRF USRPRF(" + userName + ") SPCAUT(" + authority + ")";
                String result = client.execute(cmd);
                yield StepResult.success(result, "权限设置成功", System.currentTimeMillis() - start);
            }
            case "VERIFY" -> {
                String userName = extractTargetName(op);
                var users = client.queryList(
                    "SELECT USER_PROFILE_NAME, USER_CLASS_NAME, USER_STATUS " +
                    "FROM TABLE(QSYS2.USER_INFO('" + userName + "')) X");
                if (users.isEmpty()) {
                    yield StepResult.failed("CPF2217", "验证失败", "用户不存在", System.currentTimeMillis() - start);
                }
                yield StepResult.success("OK", "验证通过", System.currentTimeMillis() - start);
            }
            default -> throw new IllegalArgumentException("未知步骤: " + stepCode);
        };
    }

    @Override
    public StepResult verifyStep(Operation op, String stepCode) {
        if ("VERIFY".equals(stepCode)) {
            return executeStep(op, "VERIFY");
        }
        return null;
    }

    private String extractTargetName(Operation op) { return op.getTargetName(); }

    private String extractGroup(Operation op) {
        try {
            var json = new com.fasterxml.jackson.databind.ObjectMapper();
            var node = json.readTree(op.getRequestData());
            return node.has("group") ? node.get("group").asText() : null;
        } catch (Exception e) { return null; }
    }

    private String extractAuthority(Operation op) {
        try {
            var json = new com.fasterxml.jackson.databind.ObjectMapper();
            var node = json.readTree(op.getRequestData());
            return node.has("authority") ? node.get("authority").asText() : null;
        } catch (Exception e) { return null; }
    }
}
```

新建 `frontend/src/components/OperationProgress.vue`：

```vue
<template>
  <el-dialog v-model="visible" :title="$t('operation.progress')" width="600px" :close-on-click-modal="false">
    <div v-if="operation" class="operation-progress">
      <el-descriptions :column="2" border size="small">
        <el-descriptions-item :label="$t('operation.type')">{{ operation.operationType }}</el-descriptions-item>
        <el-descriptions-item :label="$t('operation.status')">

        </el-descriptions-item>
        <el-descriptions-item :label="$t('operation.target')">{{ operation.targetName }}</el-descriptions-item>
        <el-descriptions-item :label="$t('operation.retries')">{{ operation.retryCount }}/{{ operation.maxRetry }}</el-descriptions-item>
      </el-descriptions>

      <el-steps :active="activeStep" finish-status="success" class="mt16">
        <el-step v-for="step in steps" :key="step.stepCode"
          :title="step.stepCode"
          :status="stepStatus(step.status)"
          :description="stepDescription(step)" />
      </el-steps>

      <div v-if="operation.errorMessage" class="mt16">
        <el-alert :title="operation.errorCode" :description="operation.errorMessage" type="error" show-icon />
      </div>
    </div>

    <template #footer>
      <el-button v-if="operation?.status === 'FAILED'" type="warning" @click="handleRetry">
        {{ $t('operation.retry') }}
      </el-button>
      <el-button v-if="canCancel" type="danger" @click="handleCancel">
        {{ $t('operation.cancel') }}
      </el-button>
      <el-button @click="visible = false">{{ $t('common.close') }}</el-button>
    </template>
  </el-dialog>
</template>

<script setup lang="ts">
import { ref, computed, onUnmounted } from 'vue'
import { ElMessage } from 'element-plus'
import { getOperation, retryOperation, cancelOperation } from '@/api/operation'
import type { Operation } from '@/api/operation'
import { useI18n } from 'vue-i18n'

const { t } = useI18n()
const visible = ref(false)
const operation = ref<Operation | null>(null)
let pollTimer: ReturnType<typeof setInterval> | null = null

const steps = computed(() => operation.value?.steps || [])
const activeStep = computed(() => {
  if (!operation.value) return 0
  const idx = steps.value.findIndex(s => s.status === 'RUNNING')
  return idx >= 0 ? idx : steps.value.filter(s => s.status === 'SUCCESS').length
})
const statusType = computed(() => {
  const map: Record<string, string> = { SUCCESS: 'success', RUNNING: '', FAILED: 'danger', CANCELLED: 'info', RETRYING: 'warning' }
  return map[operation.value?.status || ''] || 'info'
})
const canCancel = computed(() => operation.value?.status === 'REQUESTED' || operation.value?.status === 'RUNNING')

function stepStatus(status: string) {
  const map: Record<string, string> = { SUCCESS: 'success', FAILED: 'error', RUNNING: 'process', NOT_EXECUTED: 'wait', SKIPPED: 'wait' }
  return map[status] || 'wait'
}
function stepDescription(step: any) {
  if (step.durationMs) return `${step.durationMs}ms`
  if (step.ibmiReturnCode) return step.ibmiReturnCode
  return ''
}

async function open(id: number) {
  visible.value = true
  await loadOperation(id)
  pollTimer = setInterval(async () => {
    if (operation.value?.status === 'RUNNING' || operation.value?.status === 'REQUESTED') {
      await loadOperation(id)
    } else { stopPoll() }
  }, 2000)
}

async function loadOperation(id: number) {
  try { const res = await getOperation(id); operation.value = res.data }
  catch (e) { stopPoll() }
}

async function handleRetry() {
  if (!operation.value) return
  try { const res = await retryOperation(operation.value.id); operation.value = res.data; ElMessage.success(t('operation.retryStarted')) }
  catch (e) { ElMessage.error(t('common.loadFailed')) }
}

async function handleCancel() {
  if (!operation.value) return
  try { await cancelOperation(operation.value.id); operation.value!.status = 'CANCELLED'; ElMessage.success(t('operation.cancelled')) }
  catch (e) { ElMessage.error(t('common.loadFailed')) }
}

function stopPoll() { if (pollTimer) { clearInterval(pollTimer); pollTimer = null } }
onUnmounted(stopPoll)
defineExpose({ open })
</script>
```
