## 三、迁移规则

### 3.1 XML 文件命名

```
classpath:sql/as400-{module}.xml
```

已存在：
- `as400-bpcs.xml`（84 条，BPCS/ERP 相关）

新增：
- `as400-system.xml` — Job/Object/Auth/Source/Pf/DataArea/Subsystem/Sysval/MessageFile
- `as400-monitor.xml` — 监控采集 SQL

### 3.2 Statement ID 命名规范

```
{module}.{entity}.{operation}
```

示例：
```xml
<statement id="job.queue.list">SELECT JOB_QUEUE_NAME, ...</statement>
<statement id="spool.file.list">SELECT SPOOLED_FILE_NAME, ...</statement>
<statement id="auth.user.query">SELECT USER_NAME, STATUS, ...</statement>
<statement id="object.list">SELECT OBJECT_NAME, OBJECT_TYPE, ...</statement>
```

### 3.3 参数化规则

- **JDBC 参数**：使用 `?` 占位符（Service 层传参）
- **Library 占位符**：使用 `{lib}`（Service 层 replace，需 `requireIdentifier()` 校验）
- **动态 WHERE**：SQL 中使用 `WHERE 1=1` + Service 层动态拼接条件

### 3.4 Java 侧调用方式

```java
// Before (硬编码)
String sql = "SELECT USER_NAME, STATUS FROM QSYS2.USER_INFO WHERE USER_NAME = ?";
List<Map<String, Object>> rows = sqlClient.queryList(sql, userName);

// After (注册表)
String sql = sqlStatementRegistry.get("auth.user.query");
List<Map<String, Object>> rows = sqlClient.queryList(sql, userName);
```

## 四、特殊处理

### 4.1 动态 SQL（BusinessService）

`BusinessService.java` 中的 SQL 是动态拼接的（`WHERE 1=1` + 动态条件），不适合完全静态化。

**方案**：将基础 SQL 提取到 XML，动态部分在 Java 中拼接：
```xml
<statement id="business.table.query">SELECT * FROM {lib}.{tbl} WHERE 1=1</statement>
<statement id="business.table.count">SELECT COUNT(*) AS CNT FROM {lib}.{tbl} WHERE 1=1</statement>
```

### 4.2 Monitor Collector SQL

Monitor Collector 的 SQL 都是简单的单表查询，直接迁移到 XML：
```xml
<statement id="monitor.cpu.util">SELECT CPU_UTILIZATION FROM QSYS2.SYSTEM_STATUS_INFO</statement>
<statement id="monitor.disk.asp">SELECT ASP_NAME, TOTAL_SPACE, USED_SPACE FROM QSYS2.ASP_INFO</statement>
```

### 4.3 As400LoginSyncService 分页 SQL

```xml
<statement id="sync.user.list.all">SELECT AUTHORIZATION_NAME, GROUP_PROFILE_NAME FROM QSYS2.USER_INFO ORDER BY AUTHORIZATION_NAME</statement>
```

分页逻辑（OFFSET/FETCH）在 Java 中动态拼接。
