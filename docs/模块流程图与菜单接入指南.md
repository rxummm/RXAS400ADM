## 一、流程图渲染架构（现状，2026-08-19 落地）

```
真源（唯一可编辑）
├─ docs/flowcharts/modules-mermaid-source.md     ← 35 个 sequenceDiagram 代码块
├─ docs/flowcharts/01-总体架构.mmd                ← 总体架构图源文件（独立 .mmd）
└─ docs/project-flowchart-20260817.md            ← 汇总页（内嵌 01-总体架构.svg + mermaid 块）

渲染通道
├─ VitePress 站点（docs/.vitepress/config.ts 用 withMermaid() 包裹）
│    → cd docs && npm run dev    浏览器直接渲染 mermaid 代码块（无需生成文件）
│    → cd docs && npm run build  产出 dist/flowcharts/*.html
└─ node docs/flowcharts/render-all.cjs
     → 只处理 *.mmd（通过 kroki.io POST 渲染成 .svg），不处理 md 里的代码块
```

要点：

- **`modules-mermaid-source.md` 里的 mermaid 代码块是唯一真源**，改它 → dev server 热更新 / 重新 build，图自动变。
- `01-总体架构.svg` 是 `01-总体架构.mmd` 经 kroki 渲染的**产物**，不要手改 SVG，改 `.mmd` 后重跑 `render-all.cjs`（依赖外网 kroki，偶发 30s 超时，属服务端波动）。
- 站点里 mermaid 块渲染依赖 `docs/package.json` 的 `vitepress-plugin-mermaid@2` + `mermaid@11`。

### 2.2 时序图语法约定（与现有图保持一致）

```mermaid
sequenceDiagram
    actor U as 用户                                        <!-- 参与者别名：actor/participant X as 标签 -->
    participant Ctrl as XxxController
    participant Svc as XxxService
    participant AS400 as AS400ClientProvider
    participant IBMi as IBM i (AS400)

    U->>Ctrl: GET /api/v1/xxx 🔒 PERM_CODE          <!-- 消息 + 权限码 emoji -->
    Ctrl->>Svc: doSomething(...)
    Svc->>AS400: JTOpenCommandClient.execute(...)
    AS400->>IBMi: 执行命令
    IBMi-->>Ctrl: 结果

    Note right of Svc: 📖 rx_xxx<br/>说明文字        <!-- 数据表读写 + 说明 -->
    Note over U: 阶段标题

    alt 成功分支
        ...
    else 失败分支
        ...
    end

    loop 每台服务器
        ...
    end
```

- 图例：`📖 读表 / ✏️ 写表 / 🔒 权限校验 / ⚡ 异步 / 🗄️ IBM i 系统表`。
- `actor` / `participant` 的 `as 别名` 语法要求 mermaid ≥ 9.4（现装 11.x 无此限制）。
- 表格里的表名、权限码用反引号包裹（`rx_xxx`、`PERM_CODE`）。
- 行文保持「前端 → Controller → Service → AS400Client → IBM i」链路，写明每步表读写。

## 四、把流程图页面挂进系统侧边栏菜单

### 4.1 现状约束（实测结论）

- 前端是**静态路由 + 后端菜单只做侧边栏渲染**：路由全部硬编码在 `frontend/src/router/index.ts`；后端 `/api/v1/auth/menu` 只下发 `MenuVO{path, title, icon, children}`（`backend/rxas400adm-system/.../vo/MenuVO.java`），**没有 component/url/type 字段下发**。
- `rx_menu` 表有 `component`（懒加载路径）但**不参与**前端路由解析，仅菜单管理页维护用。
- **全前端 0 处 `window.open` / `target=_blank` / iframe 支持**，菜单点击只走 `el-menu router` 内部跳转（`frontend/src/layout/LayoutSidebar.vue` / `SubMenu.vue`）。

### 4.2 方案 A：内嵌 iframe 页面（推荐，贴合现有架构）

菜单指向一个内部路由 `/flowcharts`（注意 `/docs` 已被「文档管理」占用，不能用嵌套子路径），页面用 `<iframe>` 嵌入 docs 站点流程图页。改动最小，不动菜单模型，只加一条菜单数据。

**Step 1 — 新建 Vue 页面 `frontend/src/views/flowcharts/index.vue`**

```vue
<template>
  <div class="page-container page-container--fit">
    <div class="table-wrapper">
      <iframe :src="docsUrl" class="docs-frame" :title="$t('menu.flowcharts')" />
    </div>
  </div>
</template>

<script setup lang="ts">
import { computed } from 'vue'

defineOptions({ name: 'Flowcharts' })

const DOCS_BASE = (import.meta.env.VITE_DOCS_URL as string | undefined) || 'http://localhost:5174'
const docsUrl = computed(() => `${DOCS_BASE}/flowcharts/modules-mermaid-source`)
</script>

<style scoped>
.docs-frame {
  flex: 1;
  min-height: 0;
  width: 100%;
  border: none;
}
</style>
```

> - `.table-wrapper` 是 flex 容器（`page-container--fit` 下 `flex:1`），iframe 用 `flex:1` 撑满，不要用 `height:100%`（无效果）。
> - docs 地址走构建环境变量 `VITE_DOCS_URL`，缺省回退 `http://localhost:5174`（前端 dev 占 5173 时 docs 自动落 5174，见 §2.3）；生产在 `.env.production` 配置 docs 站点对外地址，避免 localhost 带进生产。

**Step 2 — 静态路由 `frontend/src/router/index.ts`**

在 Layout 的 `children` 数组追加（child 用相对路径，全路径 `/flowcharts` 与菜单 `path` 一致）：

```ts
{
  path: 'flowcharts',
  name: 'Flowcharts',
  component: () => import('@/views/flowcharts/index.vue'),
  meta: { title: 'menu.flowcharts', cached: true },
},
```

**Step 3 — Flyway 新增菜单 V47**

`backend/rxas400adm-app/src/main/resources/db/migration/V47__add_flowcharts_menu.sql`（**已落地**）：

```sql
INSERT INTO rx_menu
    (parent_id, menu_name, menu_type, title, path, component, perms, icon, sort, visible, status, admin_only, created_time, updated_time)
SELECT NULL, '模块流程图', 2, 'flowcharts', '/flowcharts', 'views/flowcharts/index.vue', NULL, 'Connection', 99, 1, 1, 1, NOW(), NOW()
WHERE NOT EXISTS (SELECT 1 FROM rx_menu WHERE title = 'flowcharts' AND menu_type = 2);
```

- `admin_only=1`：仅管理员可见，不占权限码（普通角色看不到，省去 `rx_role_menu` 授权）。
- `menu_type=2` 叶子页面、`title` 是 i18n key、`sort=99` 排末尾。

**Step 4 — i18n 双语**

`frontend/src/i18n/lang/zh-CN/menu.ts` 与 `en-US/menu.ts` 的 `menu` 段各加一条（key 必须双语齐，否则 `npm run check:i18n` 失败）：

```ts
// zh-CN/menu.ts
menu: { ..., docs: '文档管理', flowcharts: '模块流程图', ... }
// en-US/menu.ts
menu: { ..., docs: 'Documents', flowcharts: 'Flowcharts', ... }
```

**Step 5 — 门禁影响（必须同步）**

| 门禁 | 影响 | 处理 |
| --- | --- | --- |
| `scripts/check-v38-consistency.mjs` | V38 种子静态一致 | `V38_EXPECT_*` 保持与 V38 种子一致（90/44），**不要改** |
| `scripts/verify-fresh-db.sh` | 全新库菜单计数 +1（全量 = V38 种子 90 + V47 增量 1 = 91，`2:44`→`2:45`） | 在脚本 `POST_V38_MENUS_BY_TYPE` 增量里登记 V47 的 `"2:1"`（已落地）；后续迁移新增菜单继续累加 |
| `frontend npm run check:i18n` | 新增 key | zh/en 都加即过 |
| 路由守卫 | 未登录/未授权跳转 | 菜单路径与静态路由一致即可；admin_only 不参与普通角色菜单 |

**验证**：登录 admin → 侧边栏出现「模块流程图」→ 点击进入 iframe 页面 → 看到 docs 流程图。

### 4.3 方案 B：外链新标签页（改动三层，需谨慎）

如果希望点击菜单在**新标签页**打开 docs 页面（不走 iframe），需要：

1. **DB**：新 Flyway 迁移给 `rx_menu` 加 `url` 列（`VARCHAR(512) NULL`），并 INSERT 一行 url 菜单。
2. **后端**：`MenuVO.java` 加 `url` 字段，`MenuService.toMenuVO()` 下发它。
3. **前端**：`SubMenu.vue` 叶子渲染处增加分支——`menu.url` 存在时渲染为 `<a :href target="_blank">` 或 `window.open`。

> 影响面：`MenuVO` 结构变化 → `/auth/menu` 响应变化 → 前端类型（`api/auth.ts` 的 Menu 接口）同步；DB 加列 → `verify-fresh-db` 计数与 MANIFEST 都要动；三层都改，回归风险高于方案 A。**日常访问 docs 流程图，方案 A 足够。**

### 4.4 两种方案对比

| 维度 | 方案 A：iframe 内嵌 | 方案 B：外链新标签页 |
| --- | --- | --- |
| 改动范围 | 1 个 Vue 页 + 1 条路由 + 1 条菜单数据 + i18n | DB 列 + MenuVO + SubMenu.vue + 前端类型 + 菜单数据 |
| 菜单模型 | 不动 | 需加字段 |
| 用户体验 | 站内嵌框，导航不离开 | 新标签页，独立窗口 |
| docs 部署 | 需 docs 站点 URL 可达（跨端口 iframe 允许，VitePress 无 X-Frame-Options 拦截） | 只需 URL 可达 |
| 门禁影响 | 菜单计数 + 文档 | 菜单计数 + MANIFEST + 前端类型检查 |
| 风险 | 低 | 中高 |

### 4.5 部署注意

- 前端与 docs 站点是两个独立进程/产物：开发期前端 5173 + docs 5173/5174；生产各自部署（Nginx 反代 `/` 给前端、`/docs` 或独立域名给 docs 站点）。
- 方案 A 的 docs 地址走构建环境变量 `VITE_DOCS_URL`（`.env.development` / `.env.production`），避免把 localhost 带进生产。

## 五、常见问题（FAQ）

**Q1：直接改 `01-总体架构.svg` 可以吗？**
不行，SVG 是 `01-总体架构.mmd` 的渲染产物。改 `.mmd` → `node docs/flowcharts/render-all.cjs 01-总体架构.mmd`（依赖外网 kroki）。

**Q2：kroki 报 500 / 超时？**
服务端波动，与语法无关（已用 mermaid v10/v11 + 真实 Chrome 实测 35/35 渲染成功）。重试或等高峰期过后再跑；若频繁失败，改用站点方式看（`npm run dev` 本地渲染不经过 kroki）。

**Q3：为什么站点里图显示成代码块？**
`docs/package.json` 缺 `vitepress-plugin-mermaid` 或 `config.ts` 没用 `withMermaid()` 包裹。已落地，勿删。

**Q4：新模块加了表，流程图里表名写在哪？**
`Note right of Svc: ✏️ rx_新表`，并在文末「10.1 业务数据表」总表补一行。

**Q5：菜单加错想回退？**
删掉 V47 迁移文件（未合并时）或再发一个 V48 反删 `rx_menu WHERE path='/flowcharts'`；同时回滚 verify-fresh-db 期望值。前端对应删除页面/路由/i18n key。
