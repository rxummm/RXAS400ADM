# 七、30 天新人降本清单

### Action Item 1：定义菜单 VO 类，消除 `Map<String, Object>`（预估 3 天）

**优先级**：最高  
**范围**：`MenuService.java` + 前端 `MenuNode` 接口  
**落地步骤**：

1. 创建 `MenuVO`、`MenuTreeVO`、`TabVO` 三个具名类
2. 替换 `toMenuMap()` 和 `toMenuMapFull()` 中的 `Map<String, Object>` 为 VO
3. 前端 `MenuNode` 接口与后端 VO 对齐字段名
4. 将 `"ADMIN"` 字符串提取为 `RoleConstants.ADMIN_CODE` 常量

**预期收益**：新人修改菜单字段时 IDE 有自动补全和编译期检查，不再需要搜索 `map.put("path"` 字符串。

> **AAA-Remark（2026-08-15 复核）**：✅ 建议合理，与分层准绳 R3 方向一致（system 模块 Admin-only CRUD 属已知遗留、新增代码禁止直返 Entity）。实施提示：`userMenuData()` 返回的（menus/perms/tabs）三元组建议用具名 VO 承载；纯 VO 化预估 1-2 天即可，无需 3 天。

### Action Item 2：修复 `request.ts` 类型断言链（预估 2 天）

**优先级**：最高  
**范围**：`request.ts` + 所有 API 调用方  
**落地步骤**：

1. 修改响应拦截器，返回正确的 `AxiosResponse<T>` 类型
2. 移除 `as unknown as Promise<T>` 断言
3. 在 `ApiResponse<T>` 中标注 `data: T | null`
4. 全局搜索 `as unknown as` 并逐一修复

**预期收益**：前端 API 调用获得真正的编译期类型检查，新人调用 `fetchUsers()` 时 IDE 能提示 `UserVO` 的所有字段。

> **AAA-Remark（2026-08-15 复核）**：✅ 建议方向正确。修正：`as unknown as` 全库 **8 处**（非 4 处），且 `ApiResponse.data` 需同步标 `| null`（§5.2）——两者建议合并一次改完；风险低，可列最高优先级。

### Action Item 3：将复杂 CTE SQL 迁移到 XML Mapper（预估 1.5 天）

**优先级**：高  
**范围**：`SysMenuMapper.java` → `SysMenuMapper.xml`  
**落地步骤**：

1. 在 `resources/mapper/` 下创建 `SysMenuMapper.xml`
2. 迁移 `selectAuthorizedMenusByUserId` 的 CTE SQL
3. 在 `application.yml` 中配置 `mybatis-plus.mapper-locations`
4. 验证 SQL 可在数据库工具中直接执行

**预期收益**：新人调试菜单授权问题时，可以直接复制 SQL 到数据库客户端测试，SQL 有语法高亮和格式化。

> **AAA-Remark（2026-08-15 复核）**：✅ 建议可行。补充：需在 `application.yml` 配置 `mybatis-plus.mapper-locations`（当前 0 XML，未配置）；CTE 结果需建 resultMap（含 `SysMenu` 全部映射列）；迁移后 SQL 可直接在数据库工具调试，预估 1.5 天合理。
