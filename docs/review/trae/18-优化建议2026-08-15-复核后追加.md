# 十八、优化建议（2026-08-15 复核后追加）

> 本节基于对全文 60+ 处问题的逐一复核（`AAA-Remark`）与本仓库 2026-08-15 的落地现状，给出**可执行、按价值排序**的优化建议。与 §十七的区别：§十七是审计方的原始排期，本节是复核方结合「当前 MySQL 数据源 + 已建门禁体系」校准后的行动指引。

### A. 建议立即实施（低风险、高收益，合计约 1-2 天）

1. **request.ts 类型断言链重构**（§2.1 + §5.2 合并）：一次改动同时解决 8 处 `as unknown as` 与 `ApiResponse.data: T | null`。风险低（拦截器已解包），需跑全量 `npm run build`（vue-tsc 严格）+ `npm test` 验证调用方契约。
2. **`@Transactional(rollbackFor = Exception.class)` 全量补齐**（§11.1）：55 处裸注解批量替换（排除已正确的 6 个 Service），纯注解改动，`mvn test` 回归。
3. **TagsView `storeToRefs` 改造**（§4.2/§14.2）：消除 5 处手动同步，保留局部过滤/排序逻辑。
4. **前端内联 style 17 处收敛**（§8.4）：用 `.mt16`/`.ml8` 等既有工具类批量替换，一次 lint 回归。

### B. 建议下一个迭代实施（需小范围设计）

5. **MenuService VO 化**（§2.2/§7 Action 1）：`toMenuMap`/`userMenuData` 改为具名 VO（MenuVO + UserMenuDataVO），与前端 `MenuNode` 对齐——这是新人可读性的最大单项收益。
6. **Service 接口化试点**（§8.1）：先为 `MenuService`/`RoleService` 抽接口（2-3 个），验证收益后再铺开；不强制全量。
7. **CTE SQL 迁 XML**（§3.2/§7 Action 3）：需先配 `mybatis-plus.mapper-locations` + resultMap，迁移后 SQL 可独立调试。
8. **`SysRole` 类型收敛 + `menuType` 常量抽取**（§2.1/§8.3）：均为前端小重构，合并到一个 PR 顺手完成。

### C. 建议纳入门禁/规范（防止回归）

9. **`@Transactional` 缺 rollbackFor 纳入静态检查**（§11.1/§17 P2-3）：可仿照 `scripts/check-layering.sh` 写一条 grep 门禁（`grep -rn "@Transactional$" backend`），接入 `verify-all.sh` 与 backend CI。
10. **内联 style 纳入 lint 门禁**（§8.4）：在 `check-template-join.mjs` 同层加一条扫描（或 eslint `vue/no-static-inline-styles`），防止新代码再引入。
11. **i18n 若拆分，同步适配 `check-i18n.mjs`**（§8.5/§15.4）：门禁当前按单文件扫描，拆分后必须改为目录扫描，否则门禁失效。

### D. 建议暂缓（依赖外部条件）

12. **动态事务开关 + AS400 部署流水线**（§12/§13）：依赖 AS400 主数据源落地。落地前先完成 §11.1 的 rollbackFor 统一与 Journaling 运维清单，且**慎重评估 NoOpTransactionManager 关闭回滚的风险**（测试环境数据不可回滚，误配生产即静默数据不一致）。
13. **后端 BusinessException 全量 i18n**（§8.2）：工作量最大，先覆盖高频错误码（登录/权限/CRUD 校验），配合前端 request.ts 拦截器 code→i18n 映射表渐进推进。

### E. 文档维护建议

14. **多轮审计合订**：本报告与《CodeReview-RXAS400ADM-2026-08-14.md》《可读性与新人上手》存在同题重复（Entity 暴露、bindRoles N+1、TagsView 同步、i18n 拆分等），建议后续以合订本为唯一事实源，本报告保留为「原始审计底稿 + 复核备注」。
15. **备注格式**：本文 `AAA-Remark` 已标注「✅ 已确认 / ⚠️ 需修正 / 重复提及」三类结论；后续代码修复完成一项，可在对应 Remark 后追加「已修复」标记，形成闭环（2026-08-15 已对合订本已确认修复项补标，见各处「→ 状态」）。
16. **文档站化评估（VitePress）**：把本报告 + 合订本做成可搜索文档站的可行性——✅ **可行且成本低**：仓库已是 Vue 3 + Vite + TS 生态，VitePress 约 0.5 天可搭起（`docs/` 下建 `.vitepress` + 两篇 md 按章拆分），核心收益是全文搜索 + 侧边栏 + 锚点目录自动生成；⚠️ **代价**：① 两篇 md 需从「报告体」改为「站点体」（frontmatter / 分页），合订本 1400+ 行需按章节拆文件；② 仓库当前无 docs 构建步骤，需新增 npm script + CI；③ 与 `AGENTS.md` 门禁清单无冲突但需同步维护。**建议**：等 §十八 A 组（request.ts / rollbackFor / TagsView / 内联 style）执行完、审计内容稳定后再做，避免站点频繁变动；过渡期用本目录的 GitHub 锚点即可满足定位需求。
