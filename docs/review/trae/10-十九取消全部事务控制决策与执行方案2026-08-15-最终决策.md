# 十九、取消全部事务控制：决策与执行方案（2026-08-15 最终决策）

> **决策日期**：2026-08-15  
> **决策人**：项目负责人  
> **决策内容**：永久取消项目中全部 Spring `@Transactional` 事务控制，JDBC URL 配置 `transaction isolation=none`，项目不再支持事务回滚。

---

### 19.1 决策背景与理由

**业务特征分析**：

| 特征 | 说明 |
|------|------|
| 主要功能 | 查询 AS400 系统状态（作业、子系统、磁盘、消息队列等） |
| 写入场景 | 管理本项目自身的元数据（角色、菜单、用户、配置、字典、Webhook、通知等） |
| 写入并发量 | 低（仅管理员操作，非高并发 OLTP） |
| 数据一致性要求 | 低——角色/菜单/配置等写入失败可直接重试，无需回滚 |
| 部署环境 | AS400 (IBM i) + DB2 for i |

**核心结论**：项目是典型的"读多写少"运维管理平台，写入的表仅用于管理平台自身的配置元数据。在 AS400 环境下，开启事务回滚需要每张物理表执行 `STRJRNPF` 开启 Journaling，这带来额外的磁盘 I/O 和管理成本。取消事务控制后：

1. 无需在 AS400 上执行 `STRJRNPF`（28 张表免维护 Journal）
2. 消除 `SQL7008` 风险（表未开 Journaling 时的事务提交错误）
3. 消除 `SQL0913` 锁超时风险（长事务锁竞争）
4. 代码简化，新人上手成本降低
5. 写入操作直接写入物理表，失败即报错，可重试

### 19.3 开发规范（写入项目开发规范文档）

> **以下规范应写入项目开发规范文件（如 `CONTRIBUTING.md` 或 `docs/DEVELOPMENT-STANDARDS.md`）**

#### 规范条目：项目不使用事务控制

**适用范围**：RXAS400ADM 全项目（后端 Java 代码）

**规则内容**：

1. **禁止使用 `@Transactional` 注解**。任何方法上不得添加 `org.springframework.transaction.annotation.Transactional` 注解。
2. **禁止使用程序化事务**。不得注入或使用 `TransactionTemplate`、`PlatformTransactionManager` 进行编程式事务控制。
3. **JDBC 连接串必须包含 `transaction isolation=none`**（AS400 环境）或等效配置（MySQL 环境：`useServerPrepStmts=true` + `auto-commit=true`）。
4. **写入操作失败处理**：写入（INSERT/UPDATE/DELETE）失败时直接抛出 `BusinessException`，由前端提示用户重试。无需回滚逻辑。
5. **多表写入的先后顺序**：如果一个操作涉及多张表的写入，按"先写核心表，再写关联表"的顺序执行。如果核心表写入失败，后续关联表不会被写入（因为异常已抛出）。

**代码审查检查点**：

- CR 时检查是否有新增的 `@Transactional` 注解 → 拒绝
- CR 时检查是否有 `import org.springframework.transaction` → 拒绝
- 自动化门禁：CI 中执行 `grep -rn "@Transactional" backend/` 检查，非零退出即失败

**原因说明**：

- 项目主要功能是查询 AS400 系统状态，写入仅用于管理平台自身的元数据
- AS400/DB2 for i 环境要求物理表开启 Journaling 才能使用事务回滚，运维成本高
- 取消事务控制后，无需维护 Journal，避免 SQL7008/SQL0913 等 AS400 特有错误
- 写入失败直接报错重试，比事务回滚更简单可靠

**生效日期**：2026-08-15（立即生效）

### 19.4 执行步骤（修改代码时的操作顺序）

1. **Step 1**：修改 `application.yml` 和 `application-prod.yml`，添加 JDBC URL 中的 `transaction isolation=none` 配置（MySQL 环境用 `useServerPrepStmts=true` 等效替代）

3. **Step 3**：逐个删除每个方法上的 `@Transactional(rollbackFor = Exception.class)` 注解行（共 77 处）

### 19.5 风险评估与缓解

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 多表写入部分成功导致数据不一致 | 低 | 低 | 按"先核心后关联"顺序写入；核心表失败则异常中断，关联表不会被写入 |
| 并发写入导致竞态条件 | 极低 | 极低 | 写入场景仅管理员操作，并发量极低（< 1 QPS），实际不会发生竞态 |
| 未来业务扩展需要事务回滚 | 低 | 中 | 如需恢复事务，只需在 AS400 上执行 `STRJRNPF` + 恢复 `@Transactional` 注解即可，改动可逆 |
| AS400 未配置 `transaction isolation=none` 导致 SQL7008 | 中 | 高 | 在 AS400 部署文档中明确标注 JDBC URL 必须包含 `;transaction isolation=none;`；运维部署时由 CI/CD 流水线自动注入（见 §13） |
