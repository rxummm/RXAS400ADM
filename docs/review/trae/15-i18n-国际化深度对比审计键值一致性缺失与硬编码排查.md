### 15.3 前端组件硬编码中文排查

#### ✅ [良好实践] 前端组件中未发现硬编码中文文案

**审计方法**：搜索 Vue 模板中未使用 `$t()` 或 `t()` 的中文字符串。

**审计结果**：项目中所有用户可见的中文文案均通过 `$t('namespace.key')` 或 `t('namespace.key')` 引用 i18n 配置，未发现硬编码中文。这是项目在 i18n 工程化方面的显著亮点。

> **AAA-Remark（2026-08-15 复核）**：审计当日基本属实；但后续专项（P2-30，合订本 2026-08-15 完成）又收敛了 **5 处前端硬编码中文残留**（messageFiles 选项标签 / serverCompare、inspection、biz-data 的 host-env 拼接 / calendar 年月 / dict 占位符 / docs 默认分类 / loginLog 常量化）。→ **状态：前端硬编码中文 ✅ 已修复（P2-30，`check:i18n` 1014 key 全对齐）**

**唯一例外**：后端 `BusinessException` 消息全部为中文硬编码（参见 §8.2），这是 i18n 完整性方面的最大短板。

**结构约定**（建议在 i18n 文件头部添加注释说明）：

```typescript
/**
 * i18n 命名空间约定：
 * - common.*         → 全局通用文案（按钮、提示、状态）
 * - layout.*         → 布局组件（侧边栏、顶栏、多标签页）
 * - menu.*           → 左侧菜单/页面标题（路由 meta.title）
 * - menu.manage.*    → 菜单管理页专用
 * - <module>.*       → 各业务模块内部文案
 */
```

#### [重构建议/Info] i18n 文件体积过大（1143 行），建议按模块拆分

**当前**：`zh-CN.ts` 和 `en-US.ts` 各 1143 行，单文件体积过大。

**建议**：按命名空间拆分为独立文件：

```
src/i18n/lang/
  ├── zh-CN/
  │   ├── index.ts        # 聚合导出
  │   ├── common.ts
  │   ├── menu.ts
  │   ├── jobs.ts
  │   ├── docs.ts
  │   └── ...
  └── en-US/
      ├── index.ts
      ├── common.ts
      ├── menu.ts
      ├── jobs.ts
      ├── docs.ts
      └── ...
```

```typescript
// zh-CN/index.ts
import common from "./common";
import menu from "./menu";
import jobs from "./jobs";
// ... 30 个模块

export default { common, menu, jobs /* ... */ };
```

**预期收益**：

- 单文件从 1143 行降至 < 50 行
- Git 合并冲突大幅减少（不同模块的翻译人员不会同时修改同一个文件）
- 新人只需关注自己模块的 i18n 文件

> **AAA-Remark（2026-08-15 复核）**：与 §8.5 为**同一建议**（重复提及）。⚠️ 本仓库特有约束：拆分后必须同步适配 `frontend/scripts/check-i18n.mjs` 门禁（当前按单文件扫描）与 `frontend/package.json` 的 `check:i18n` 脚本。
